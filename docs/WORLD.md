# 월드 v2 설계 — 서브에이전트가 만드는 상황·선택지, 유저가 고르는 행동

작성: 2026-10-26 · 상위: [DESIGN.md](DESIGN.md), [SKELETON.md](SKELETON.md) · 상태: **설계 (미구현·미검증)**

## 0. 한 줄

> Director(Meta 서브에이전트)가 **상황 + 선택지**를 만들고, 플레이어가 **선택지 중 하나를 고르면**, 세계 엔진이 결과를 확정하고, 그 선택이 아이 모델의 학습 데이터가 된다.

지금(v1)은 "할머니가 X를 원한다 → 슬롯 하나 고르기" 한 종류뿐이다. v2는 상황의 종류·구성·후속 사건·선택지를 Director가 만들게 해서 세계를 넓힌다. 놀이 B(사용법 적용)가 이 안에 흡수된다.

---

## 1. 가장 중요한 제약: 작은 모델은 자유 텍스트를 못 읽는다

아이는 약 7만 파라미터 Transformer고 **닫힌 어휘(토큰)** 만 읽는다. 그래서 Director가 자유롭게 만들 수 있는 것과 없는 것을 층으로 나눈다.

| 층 | 누가 | 자유도 | 아이가 보나 |
|---|---|---|---|
| **온톨로지** (상황 태그, 물건 종류, 속성, 동사) | 개발자 고정 (데이터 파일) | 닫힘 | ○ 토큰으로 |
| **구성** (어떤 태그가 켜지고, 어떤 물건이 놓이고, 어떤 선택지를 내는가) | **Director** | 온톨로지 안에서 자유 조합 | ○ 토큰으로 |
| **서사** (장면 묘사, 대사, 이름, 분위기, 과거 사건 언급) | Director/Narrator | 자유 텍스트 | ✕ 절대 안 봄 |
| **결과** (선택의 효과, 상태 변화) | **규칙 엔진** | 규칙표로 결정 | ✕ (겪은 뒤 학습만) |

- Director의 창의성은 **조합과 서사**에서 나온다. 온톨로지를 늘리는 것은 데이터 추가(코드 변경 없음)다.
- 자유 텍스트가 아이 입력에 들어가면 안 된다 → "Meta가 대신 풀어주는" 경로가 구조적으로 차단된다.

## 2. 온톨로지 v1 (닫힌 어휘)

DESIGN 3.4/3.5의 확정표를 데이터로 옮긴다.

| 구분 | 값 |
|---|---|
| 상황 태그 | `THIRSTY` `FLOOR_WET` `DARK` `COLD` `VISITOR` `REQUEST`(할머니가 단어로 요청, v1의 find) |
| 물건 종류 (아이에게는 비공개) | cup, cloth, paper, blanket, flashlight, spoon, ball → 속성(모양·재질·크기·색)만 보임 |
| 동사 | `DRINK` `WIPE` `LIGHT` `COVER` `GIVE` `FETCH` `WAIT` |
| 장소 | house, yard (서사용 + 태그 후보) |

토큰 수: 태그 6 + 속성 ~20 + 동사 7 + 이름 32 + 슬롯/옵션 ~10 ≈ 100 이하. 물건·태그·동사는 늘려도 어휘 고정 크기(예약 슬롯)에 들어가게 둔다.

## 3. 규칙표 = 정답의 유일한 출처

선택지의 좋고 나쁨은 LLM이 아니라 **규칙표**가 정한다. `(태그, 동사, 대상 종류) → 결과`:

| 태그 | 선택지 (동사+대상) | 결과 | 가치 |
|---|---|---|---|
| THIRSTY | DRINK + cup | 해소 | +2 |
| THIRSTY | DRINK + spoon/cloth/… | 변화 없음 | 0 |
| FLOOR_WET | WIPE + cloth | 해소 | +2 |
| FLOOR_WET | WIPE + paper | paper 소모, 여전히 젖음 | +1 (부분) |
| FLOOR_WET | WAIT | 방치 → 후속 사건(할머니가 미끄러질 뻔) | −1 |
| DARK | LIGHT + flashlight | 해소 | +2 |
| COLD | COVER + blanket | 해소 | +2 |
| VISITOR | GIVE + ball | 방문이 즐겁게 끝남 | +2 |
| 어떤 태그든 | WAIT | 방치 (태그에 따라 악화/무변화) | 0~−1 |
| REQUEST(word) | FETCH + 그 단어의 종류 | 요청 충족 | +2 |
| REQUEST(word) | FETCH + 다른 종류 | 거절 | 0 |

- 가치는 `+2 해소 / +1 부분 / 0 무변화 / −1 역효과`. 같은 가치가 여럿이면 동률 최적.
- **아이 평가 = 최적(최대 가치) 선택지를 고르는가**. 무작위 기준은 선택지 수의 역수(동률 반영).
- 플레이어는 최적이 아닌 것도 고를 수 있다(틀린 시범도 그대로 학습, v1과 동일). 결과는 세계에 반영된다.
- 규칙표는 데이터 파일(`world/rules.yaml`)이라 확장이 쉽다. 새 동사/태그는 규칙 한 줄 + 토큰 한 칸.

## 4. 상황과 선택지 (v2 데이터 모델)

```python
class Option(BaseModel):          # Director가 제안, 엔진이 검증
    verb: str                     # 온톨로지 동사
    target: str | None            # 장면 속 물건 id (없으면 None, 예: WAIT)

class SituationV2(BaseModel):
    id: str
    tags: list[str]               # 켜진 상황 태그 (1~2개)
    word: str | None              # REQUEST일 때만
    scene: list[str]              # 놓인 물건 id
    options: list[Option]         # 3~5개. 엔진이 가치 계산
    location: str
    links_to: str | None          # 이어받는 과거 사건 id (후속 사건)
    # 서사(자유 텍스트)는 SituationV2에 두지 않고 Narrator 출력에만 있다
```

엔진이 계산해서 보관: `values: list[int]` (옵션별 가치). **Director에게는 값을 알려주지 않고**, 아이 입력에도 없다.

### 아이가 보는 것 (Observation v2)
```
[BOS] TAG_THIRSTY [SEP]
OPT_0 DRINK SLOT: COLOR_blue SHAPE_cylinder SIZE_small MAT_ceramic [SEP]
OPT_1 WIPE  SLOT: COLOR_red  SHAPE_flat     SIZE_big   MAT_fabric  [SEP]
OPT_2 DRINK SLOT: COLOR_red  SHAPE_flat     SIZE_big   MAT_paper   [SEP]
OPT_3 WAIT  [SEP]
ACT_PICK → OPT_k
```
- 물건 종류·가치·Director 서사·결과 힌트는 입력에 없다. 옵션 순서는 셔플. 모든 옵션이 문법상 허용(정답만 남기지 않음).
- 아이가 배워야 하는 것: "THIRSTY일 때 DRINK는 원통·도자기 대상이어야 한다", "FLOOR_WET에는 납작한 천" 같은 **(상황, 동사, 속성) 조합 규칙**.
- v1의 find 요청은 `TAG_REQUEST + NAME_xx` + 옵션 `FETCH slot`으로 표현된다 → 기존 코드 재사용.

## 5. Director v2 — 무엇을 어떻게 만들게 하나

### 5.1 입력 (프롬프트 컨텍스트, 구조화 JSON)
- 세계 상태 요약: 하루/시간, 위치, 물건 목록(속성만+이름), NPC 위치, **미해결 사건**(open issues), 최근 N개 이벤트
- 커버리지: 태그·동사·종류별로 지금까지 요청/시범된 횟수 (균형 잡힌 교육과정)
- 아이의 약점 요약: 퀴즈 오답이 많은 태그·동사 (정답은 안 줌, "복습이 필요한 주제"만)
- 온톨로지 목록, 출력 스키마, 금지 규칙

### 5.2 출력 (JSON, 카드 2장)
```json
{"cards":[{
  "tags":["FLOOR_WET"], "location":"house",
  "objects":[{"kind":"cloth","color":"blue","size":"big"},{"kind":"paper","color":"red","size":"small"},{"kind":"cup","color":"red","size":"small"}],
  "options":[{"verb":"WIPE","target":0},{"verb":"WIPE","target":1},{"verb":"DRINK","target":2},{"verb":"WAIT","target":null}],
  "links_to":"evt_12",
  "teaser":"The cup Grandma was holding is on the floor, and so is the water."
}]}
```
`teaser`와 서사는 사람용 텍스트. 아이 입력으로 가지 않는다.

### 5.3 검증 (엔진, 실패 시 템플릿으로 대체)
1. 태그·동사·종류가 온톨로지에 있음, 스키마 일치
2. 옵션 수 3~5, 대상이 장면에 있음, 중복 옵션 없음
3. **최적 선택지가 최소 1개 존재** (가치 +2 또는 최대값), 최적이 아닌 선택지도 1개 이상 (선택이 의미 있어야 함)
4. 전제조건: 소유·수량·위치·이미 해결된 사건 반복 금지, `links_to`가 실제 과거 이벤트
5. 퀴즈 장면 해시와 충돌 금지 (v1과 동일)
6. 정답 위치 편향 검사: 최적 옵션 인덱스가 한쪽으로 쏠리지 않게 엔진이 셔플

### 5.4 Director가 못 하는 것
- 가치(정답)를 정하거나 알려주기, 결과 확정, 아이의 행동 대신 선택, 규칙 변경, 입력 토큰 밖의 물건/동사 도입

### 5.5 폴백
태그별 템플릿 생성기 (현재 `scenegen`의 일반화). LLM이 없거나 검증에 실패해도 게임은 같은 온톨로지로 계속된다.

## 6. 세계와 이야기가 살아 있게 만드는 것

- **지속 상태**: 물건 상태(젖음/깨짐), 수량(paper 소모), 태그의 해결 여부, NPC 위치. 모두 이벤트 로그에서 접어서 만든다(현재 구조 유지).
- **후속 규칙** (엔진이 결정, Director는 활용): 
  - 방치된 `FLOOR_WET` → 다음 상황에서 `VISITOR`가 미끄러질 뻔함 (태그 승격)
  - `COLD` 방치 → 다음 날 아침 `SNEEZE`(서사) + `COLD` 재발
  - `LIGHT`로 해결한 `DARK` → 마당 탐험 상황(`discovery`) 해금, 새 물건 등장
  - 아이의 올바른 선택으로 해결 → 새 물건·새 이름을 가르칠 기회
- **3일 소아크**: Director가 하루 단위로 "오늘의 흐름"(예: 비 오는 날 → 젖은 바닥·추위·손님)을 제안. 엔진은 각 카드를 검증할 뿐 줄거리를 강제하지 않는다.
- **카드 2장 선택**: 미리보기는 태그+teaser. 플레이어의 전략은 "아이가 약한 주제를 고를까, 새 주제를 고를까".

## 7. 플레이어의 다양성 손잡이 (지난 단계의 빈틈 해결)

옵션 안에 **같은 종류의 개체가 여러 개** 놓이게 한다 (예: 컵 3개 — 빨강 작은 것, 파랑 큰 것, 초록 작은 것). DRINK를 어느 컵으로 시범할지가 플레이어의 선택이므로, 색·크기 다양성은 **플레이어가 어떤 개체를 골라 보여주느냐**로 결정된다.
- 좁게 가르치기 = 늘 같은 색 컵만 고르기 → 탐침 패널에 색 편향으로 드러남 (이미 검증된 현상)
- 엔진 규칙: 같은 종류가 여러 개인 옵션은 모두 동률 최적 (색·크기는 결과에 영향 없음)

## 8. 학습·평가 변화

| 항목 | v1 | v2 |
|---|---|---|
| 모델 출력 | `SLOT_k` | `OPT_k` (옵션 인덱스) |
| 정답 | 요청 종류의 슬롯 1개 | 최대 가치 옵션(동률 허용) |
| 어휘 | 속성+NAME | + 태그·동사·OPT 토큰 |
| 증강 | 슬롯 셔플, 방해 물건 재추첨 | 옵션 셔플, 방해 옵션/물건 재추첨 (**최적 옵션과 그 대상은 건드리지 않음**) |
| 퀴즈 | 새 장면 8문제 | 새 (태그, 물건, 옵션) 조합 8문제, 장면 해시 격리 |
| 탐침 | 속성 대비 | 속성 대비 + **동사 대비**(같은 대상에서 어떤 동사를 고르나) + 태그별 |
| 새로 필요한 검사 | — | 태그를 무시하고 대상 속성만 보는지(`tag-blind`), 동사만 고르는지 |

평가 지표: 최적 선택률(주), 평균 가치, 무작위/학습 전 대조, 태그별 정확도(약점 지도 → Director 커리큘럼 입력).

## 9. 정직성 규칙 (v1에서 계승 + 추가)

- 아이 입력에 가치·종류·Director 서사·결과가 없다 (테스트: 직렬화 필드 검사)
- 최적 정답은 규칙표에서만 나온다. Director의 의견은 정답이 아니다
- Director가 "이 선택지가 좋아 보이게" 서사로 유도해도 아이는 그 텍스트를 못 본다. 단, **플레이어는 본다** → 플레이어가 서사에 속아 틀린 시범을 줄 수 있다. 이는 의도된 게임성(데이터 품질)이지만 서사가 정답을 노골적으로 말하지 않게 프롬프트로 제한한다
- 엔진/규칙표가 학습된 능력을 대신 수행하지 않는다 (엔진은 평가·결과 확정만)

## 10. 구현 순서 (남은 일정에 맞춰)

| 단계 | 내용 | 게이트 |
|---|---|---|
| **P1 타당성 (먼저)** | 온톨로지·규칙표·옵션 인코딩만 만들고 합성 플레이어로 "상황→옵션 선택" 학습 실험 | 하루 6~10상황, 3~4일 차 최적 선택률 80%+, 시드 편차 확인. **안 되면** 태그·동사 수를 줄이거나 옵션 수를 줄임 (기존 v1로 후퇴 가능) |
| P2 엔진 v2 ✅ (13절) | `SituationV2`, 옵션 결과·가치·후속 규칙, Session 일반화, find를 REQUEST 태그로 흡수, 기존 테스트 이관 | 불변식 테스트(멱등·재개·누출·퀴즈 격리) 유지 |
| P3 Director v2 ✅ (14절) | 프롬프트/스키마/검증/템플릿 폴백, 커리큘럼 입력, Narrator v2, MockClient로 전체 경로 | 잘못된 제안이 엔진에서 걸러지고 폴백으로 진행 |
| P4 실제 API (준비 완료·키 대기, 15절) | `muse-spark-1.3-contributor` 연결(키 발급 후), 응답 로그·캐시, 실제 Director 품질 점검 | 검증 통과율, 지연, 폴백 비율 측정 |
| P4.5 세계·선택지 강화 (16절, 제안) | 선택지 문법·카드 배지·스토리릿 아크·(웨이브) | 기존 게이트 유지 + 어려운 오답 패널 |
| P4.6 부모 행동 이식 ✅ (20절) | `Talk`/`Command` 이벤트, 관심 예산, 같은 지표를 `Session`에서 재현, 합성 부모 | 기존 게이트와 소수점까지 동일 + E-A가 엔진 경로에서 재현 |
| P5 UI | 상황 카드·선택지·결과 서술·머릿속 패널 (웹) | 5분 플레이 |

P1이 이 설계의 **최대 위험 검증**이다. 아이가 (상황 태그 × 동사 × 대상 속성) 조합 규칙을 3~4일 분량 데이터로 배울 수 있는지가 v1의 "이름→종류"보다 어렵다. 같은 하이퍼파라미터가 그대로 통할 거라고 가정하지 않는다.

## 11. 미정 사항

| 질문 | 기본안 |
|---|---|
| 한 상황의 태그 수 | 1개로 시작, 2개 동시 상황(우선순위 선택)은 P1 통과 후 |
| 옵션 수 | 4개 (최적 1+, 함정 1+) |
| 온톨로지 크기 | 태그 6, 종류 7, 동사 7 — P1에서 학습이 되는 한 유지 |

## 12. P1 타당성 실험 결과 (2026-10-26)

**만든 것** (v1 코드와 분리된 프로토타입): `server/world/world2.py`(온톨로지·규칙표·상황/선택지 생성기), `server/learning/codec2.py`(토큰·인코딩·손실·증강·퀴즈 채점), `scripts/exp_world2.py`(하네스), `tests/test_world2.py`(7개: 규칙표, 생성기 불변식, 관찰에 종류·가치·서사 없음, 해시 순서 무관·퀴즈 격리, 인코딩·마스크, 증강이 선택한 옵션을 보존, 학습 배관). 전체 pytest 48개 통과. `Learner`·`TinyLM`은 손실/증강/어휘 크기를 주입할 수 있게만 일반화했고 v1 동작은 그대로다.

**설정**: 주제 = 문제형 5(THIRSTY·FLOOR_WET·DARK·COLD·VISITOR) + 단어 요청 4(REQUEST:cup/cloth/paper/ball). Director 대역이 가장 덜 연습한 주제 2개를 카드로 내고 합성 플레이어가 무작위로 하나를 고른다. 합성 플레이어는 규칙표의 최적 옵션을 시범으로 보이거나(50%), 아이가 시도한 것에 칭찬/교정한다. 아이는 태그·단어 토큰·옵션의 동사와 대상 **속성**만 본다. 평가 = 학습에 안 쓴 장면(해시 격리)에서 최적 옵션을 고르는 비율(argmax). 튜닝은 시드 100~119, 검증은 **한 번도 쓰지 않은 시드 200~239(40개)**. 무작위 기준 ≈ 0.29~0.31.

### 검증 결과 (시드 200~239, 3일 차 평균 / 최저 / 80% 이상 시드 수 | 10일 차 평균 / 최저)

| 설정 | 3일 차 | 3일 차 ≥80% | 6일 차 | 10일 차 |
|---|---|---|---|---|
| 학습 끔 (대조군) | 0.29 / 0.21 | 0/40 | 0.29 | 0.29 / 0.21 |
| 전체 주제, 기본(2층, lr 1e-3), 하루 10상황 | 0.64 / 0.52 | 1/40 | 0.87 | 0.94 / 0.83 |
| 전체 주제, 3층·lr 2e-3, 하루 10상황 | 0.71 / 0.59 | 4/40 | 0.92 | 0.96 / 0.86 |
| 전체 주제, 3층·lr 2e-3, **하루 16상황** | **0.88 / 0.75** | 36/40 | 0.97 | 0.98 / 0.89 |
| **문제형 5개만**, 3층·lr 2e-3, 하루 8상황 | **0.93 / 0.80** | 40/40 | 0.97 | 0.99 / 0.93 |
| **문제형 5개만**, 3층·lr 2e-3, 하루 10상황 | **0.96 / 0.83** | 40/40 | 0.99 | 0.99 / 0.93 |
| 문제형 + 두 문제 동시(30%), 하루 10상황 | 0.89 / 0.76 | 36/40 | 0.97 | 0.99 / 0.94 |

학습 지연: 평균 0.5~0.9초, 최대 1~2.1초 (시드 16개 병렬 실행 중 측정이라 단독 실행보다 길다).

### 결론

1. **P1 게이트 통과(조건부)**: 랜덤 초기화한 작은 모델이 "상황 태그 × 동사 × 대상 속성" 규칙을 플레이어의 선택만으로 배운다. 문제형 5개는 하루 8~10상황, 3일 차에 평균 0.93~0.96이고 40개 시드 모두 80%를 넘는다(대조군 0.29).
2. **병목은 단어 요청(REQUEST)**: 단어 4개를 각각 하나의 주제로 두면 단어당 예시가 적어 3일 차에 0.5~0.6대에 머물고(하루 10상황), 하루 16상황이어야 0.76~0.84가 된다. 문제형 태그는 규칙 하나가 곧 한 주제라서 예시 4~5개로 배워진다.
3. **요청 단어를 하나의 주제로 묶어도 개선되지 않았다**(튜닝 시드: 0.66~0.69). 단어마다 예시가 더 줄어서다.
4. **방해 옵션 재추첨 증강이 크게 기여**: 끄면 3일 차 0.51, 켜면 0.66(튜닝 시드, 하루 10상황). 일반화 실패(외우기) 문제가 v1과 같은 방식으로 나타나고 같은 방식으로 완화된다. 재추첨은 규칙표를 쓰지 않고 시범에 이미 들어 있는 정보만 쓴다(테스트됨).
5. **태그를 읽고 고르는가**: 문제형 주제에서 입력 태그를 다른 태그로 바꿔치기하면 정답률이 0.99 → 0.41로 떨어진다(무작위 0.30). 태그를 무시하고 물건만 보는 지름길이 아니다. 다만 0.41은 무작위보다 높아서 태그와 무관한 약한 단서(예: 장면에 흔한 물건)도 일부 쓴다.
6. **3층·lr 2e-3**이 2층·lr 1e-3보다 3일 차 +0.07 (튜닝·검증 시드 모두 같은 방향). d_model 96, 스텝 100은 비슷하거나 작은 이득이라 채택하지 않았다.

### 한계 / 주의

- 합성 플레이어는 항상 규칙표의 최적 옵션을 시범으로 보이므로 사람이 틀린 시범을 주면 낮아진다(의도된 동작).
- 두 문제가 동시에 켜지는 상황은 3일 차 0.84~0.85로 단일 문제보다 낮다. 학습은 되지만 데이터가 더 필요하다.
- 규칙표의 값(0/1/2/−1)은 개발자가 정했고, 값이 둘뿐인 "해소 / 부분" 구조라 실제 게임의 풍부한 결과와는 거리가 있다.
- Director의 LLM 출력 품질·검증 통과율은 **아직 측정하지 않았다**(P3~P4). 이 실험의 상황은 모두 템플릿 생성기가 만들었다.
- 하이퍼파라미터는 시드 100~119로 약 20개 조합을 보고 골랐고 검증 시드 200~239로 후보 6개를 한 번씩 돌렸다.

## 13. P2 엔진 v2 결과 (2026-10-26)

**결정 반영**: 문제형 중심, 단어 요청은 후속 사건으로 하루 최대 1개(`REQUESTS_PER_DAY=1`), 하루 8상황(`per_day=8`, 10도 지원), 모델 3층 d64 (약 109k 파라미터, 온라인 lr 2e-3).

### 만든 것 (4절과 달라진 점)

- 물건은 `scene` id 목록이 아니라 **상황 안에 내장**(`Situation.objects`). 옵션은 `OptionSpec(verb, target)`이고 가치는 엔진이 규칙표로 계산한다(`option_value/values/optimal/outcome_of`).
- `links_to`는 과거 **미해결 이슈 id**(`"<상황 id>:<태그>"`)를 가리킨다. 이슈는 `WorldState.issues`에 쌓이고 해결되면 닫힌다.
- 이벤트 소싱: 명령(Show/Try/Praise/Correct/Skip/OfferCards/PickCard)은 `action_id`로 멱등이며 거부 사유는 `RuleError(code)`. 이벤트에는 규칙표 결과(`option, value, outcome, tag_values, was_right`)가 기록되어 재생(fold)만으로 상태가 복원된다.
- 세계 기억: 확대(`ESCALATION`: FLOOR_WET을 `worse`로 끝내면 VISITOR), 장소 해금(`UNLOCKS`: DARK 해결 → yard), 이름 붙일 수 있는 물건(`nameable`) → 하루 1개 한도의 단어 요청.
- 코드 정리: v1 `catalog/scenegen/world2/codec2/dataset/tokenizer/vocab/probe`는 삭제. v1 스냅샷은 `archive/v1_skeleton_2026-10-26.tar.gz`, v1 실험 스크립트는 `scripts/legacy_v1/`(아카이브에서만 실행 가능).

### 엔진이 거부하는 것 (테스트됨)

온톨로지 위반(`validate_situation`), 퀴즈 해시와 충돌하는 장면(`Engine.forbidden`), 같은 옵션이 두 번 나오는 카드·두 카드가 동일한 경우, 재사용된 id, 해금되지 않은 장소, 후속 태그 규칙 위반, 하루 단어 요청 한도 초과, 단어/토큰 불일치.

### 불변식 테스트 (pytest 65개, 약 30초)

- 아이 입력에 종류·가치·결과·서사 없음. 관찰 해시는 옵션 순서와 무관. 퀴즈 장면은 학습에 못 들어감.
- AST 테스트: `server/learning`은 `agents`/`game`을 import하지 않고, 학습 코드(codec/learner/policy/model/체크포인트)는 규칙표를 참조하지 않는다.
- 재개: 같은 이벤트 로그에서 같은 상태. 저장은 `ONTOLOGY_HASH`에 묶이고 불일치하면 `Session.load`가 `ValueError`.
- Director 제안이 틀리면 템플릿으로 대체되어 게임이 계속된다(Mock 클라이언트로 전체 경로 확인).

### 게이트 (`scripts/exp_gate.py`, 실제 `Session` 경유, 시드 200~239, 10일)

합성 플레이어는 규칙표 최적 옵션을 시범으로 보이거나 아이의 시도에 칭찬/교정한다. 점수 = 평가 퀴즈(학습에 안 쓴 장면)에서 최적 옵션 선택률.

| 설정 | 문제형 3일 차 (평균 / 최저 / ≥80% 시드) | 6일 차 | 10일 차 (평균 / 최저) | 요청형 3일 차 → 10일 차 |
|---|---|---|---|---|
| 하루 8상황 | **0.92** / 0.75 / 38/40 | 0.97 | 0.99 / 0.92 | 0.41 → 0.75 |
| 하루 10상황 | **0.95** / 0.78 / 39/40 | 0.97 | 0.98 / 0.85 | 0.42 → 0.74 |
| 하루 8상황 + 플레이어 실수 10% | 0.86 / 0.65 / 29/40 | 0.95 | 0.97 / 0.85 | 0.41 → 0.66 |
| 학습 끔 (대조군, 시드 200~219) | 0.29 / 0.20 / 0/20 | 0.29 | 0.29 / 0.20 | — |

- 기준(3일 차 문제형 ≥80%를 대부분의 시드에서): **통과**. 학습 전(ckpt_000) 0.30, 무작위 0.31, 대조군 0.29.

- 학습 지연: 평균 0.7초, 최대 1.4초(16프로세스 병렬 중 측정).
- **요청형은 기준 미달이며 따로 보고한다.** 3일 차 0.41(무작위 0.27)이고 10일 차에야 0.75. 단어당 예시가 하루 ≈1개 이하라 예상된 결과이며, 문제형 중심 결정(단어는 보조)과 맞다. 10일간 단어 요청 약 9.6개, 알게 된 단어 약 3개.

### 한계 / 주의

- **후속 사건은 플레이어가 틀려야 생긴다.** 실수 없는 합성 플레이어는 이슈가 남지 않아 후속 카드와 두 문제 동시 상황이 0건이다. 실수 10% 설정에서만 후속 카드 약 8.3장, 두 문제 동시 0.1건. 이 경로는 단위 테스트로 검증했지만 게이트 수치로 충분히 쌓이지 않았다.

- 저장은 온톨로지 해시에 묶여 있어 규칙표를 고치면 이전 저장은 못 읽는다. 크래시 일관성은 경고만 한다(쓰기 중 중단 시 마지막 이벤트 유실 가능).

## 14. P3 Director v2 · Narrator v2 결과 (2026-10-27)

실제 LLM은 아직 없다(P4). 그래서 이 단계의 목표는 "**LLM이 무엇을 내놓아도** 게임이 안전하게 돌아가고, 진짜 모델이 오면 품질을 잴 수 있는 배관을 갖추는 것"이다. 검증은 Mock 클라이언트와 일부러 틀리게 만든 가짜 클라이언트로 했다.

### Director v2

- **프롬프트** (`agents/director.py` SYSTEM + `agents/glossary.py`): 역할, 카드 스키마, 좋은 장면 구성(풀 수 있는 물건과 그럴듯한 오답, 오답 옵션 최소 1개, 색·크기 변화), 커리큘럼 규칙, 금지 규칙, `previous_error` 처리. 글로서리는 문제·동사·물건이 **무엇인지**(상식)만 말하고 어떤 물건이 어떤 문제를 푸는지는 말하지 않는다(테스트됨). 프롬프트에 가치·최적·퀴즈·체크포인트·보상 같은 말이 없는 것도 테스트한다.
- **커리큘럼 입력** (`DirectorContext`): 기존 `topic_counts`·`open_issues`·`nameable`·`requests_left`·`unlocked`에 더해 `review_topics`(직전 저녁 퀴즈에서 정확도 0.6 미만인 주제, 약한 순; 주제 이름만 주고 정답·점수는 안 준다)와 `recent_topics`(최근 고른 6개). 둘 다 이벤트에서 접어 만든 `WorldState` 필드다(`QUIZ_TAKEN`, `CARD_PICKED`).
- **수리 루프**: 제안이 스키마나 엔진 검증을 통과 못 하면 이유(`previous_error`, 300자 이내)와 자기 이전 답을 붙여 **한 번** 다시 묻고, 그래도 안 되면 템플릿. 두 카드가 같은 주제이면 거부한다(플레이어에게 선택지가 있어야 한다).
- **하루 테마** `theme`: Director가 쓰는 한 줄(120자 이내). `OfferCards` 이벤트에 저장되고 화면에만 나온다.
- **템플릿 폴백도 커리큘럼을 따른다**: 방금 한 주제는 뒤로, 복습 주제는 덜 연습한 것으로 취급, 두 카드는 항상 다른 주제.
- **티저 가드**: 사람용 미리보기 문장에 물건 이름·내부 토큰·"정답" 류 말·마크업·길이 초과가 있으면 **그 문장만** 버리고(카드는 유지) Narrator의 도입 문장을 대신 보여준다.

### Narrator v2

- 고정 문구(P2)는 그대로 **항상 유효한 폴백**이다. `NarratorAgent`가 LLM에게 (a) 장면 도입, (b) 선택 결과의 뒷문장을 쓰게 하고 가드를 통과한 것만 쓴다.
- **엔진 사실은 엔진의 말로**: "You wipe the floor with the big red cloth."는 항상 고정 문장이고, LLM은 그 뒤의 결과 한 문장만 쓴다. 장소 해금·새 이슈·이름 붙일 물건 알림(`world_note`)도 고정이다.
- **도입 프롬프트에는 물건·옵션 정보가 없다**(테스트됨). 그래서 도입 글이 정답을 귀띔할 수 없다. 가드는 어떤 물건 이름도 허용하지 않는다.
- **결과 가드**: 고른 물건 외의 이름 금지, 열리지 않은 장소 언급 금지, 엔진의 결과 라벨과 모순(해결됐다는데 "worse", 악화됐다는데 "solved" 등) 금지, REQUEST 도입에는 그 단어가 반드시 들어가야 함, 내부 토큰·마크업·길이 초과 금지.
- 같은 상황의 글은 캐시되어 화면을 다시 그려도 바뀌지 않는다. 글은 아이 입력과 학습 데이터에 영향이 없다(테스트됨: 관찰 해시 불변, `codec`가 서사·티저·테마를 참조하지 않음).

### 관측용 배관 (P4 준비)

- `AgentStats`: 호출 수, 사용 가능했던 답(ok), 수리 후 성공, 폴백, 클라이언트 없음, 평균 지연. `Session.llm_stats()`와 `autoplay` 마지막 줄로 본다.
- 세이브 폴더의 `llm_log.jsonl`: Director·Narrator 호출마다 한 줄(source, ok, attempts, error, seconds). 진단용이며 fsync하지 않는다.

### 검증

- pytest 93개 통과(약 29초). 새 테스트 28개: 글로서리 완전성, 상태 접기, 템플릿 커리큘럼, 프롬프트 내용 금지어, 수리 루프(1회 수리, 2회 실패 후 폴백, 세 번째 시도 없음), 클라이언트 없음/장애 시 게임 진행, 텍스트 가드·결과 가드 표, Narrator 폴백 8종, Mock Narrator가 모든 태그×라벨에서 가드를 통과, 세션 전체 경로와 로그.
- 게이트(시드 200~239, 하루 8상황, 새 템플릿 커리큘럼 + Mock 에이전트): 문제형 3일 차 **0.90**(최저 0.73, 80% 이상 39/40), 실수 10%에서 0.87(33/40). P2의 0.92·0.86과 같은 범위다(시드 편차 0.06). 즉 커리큘럼·에이전트 배관이 학습 성능을 떨어뜨리지 않는다. 태그 바꿔치기 0.98 → 0.36.

### 한계 / 주의

- **진짜 LLM을 아직 만나지 않았다.** 프롬프트는 가설이다. 검증 통과율·수리 성공률·폴백 비율·지연·글 품질은 P4에서 `llm_stats`로 잰다. 프롬프트가 "풀 수 있는 물건을 올려라"를 상식에만 맡기므로 통과율이 낮으면 글로서리에 장면 예시를 넣거나 수리 횟수를 늘린다.
- **커리큘럼의 효과는 아직 측정하지 못했다.** 합성 플레이어가 카드를 무작위로 고르고 복습 주제가 거의 안 생겨서 게이트에서는 `review_topics`의 영향이 보이지 않는다. 사람이 약한 주제를 고르는 전략을 쓸 때의 효과는 P5 이후 확인한다.
- 가드는 단어 매칭이라 완곡한 힌트("Grandma looks at the shelf")는 못 거른다. 정답 노출은 막지만 서사의 유도 가능성은 설계 9절대로 **플레이어가 서사에 속을 수 있다**는 게임성으로 남는다.
- Mock Narrator는 목소리를 다르게 하려고 변형 문구를 쓸 뿐이고 실제 LLM 문장 수준이 아니다.
- 폴백이 전부 조용히 일어나면 게임이 계속 템플릿으로만 돌 수 있다. 그래서 `llm_stats`·`llm_log`에서 폴백 비율을 볼 수 있게 했고, UI(P5)에서 표시할 필요가 있다.

다음: P4 `muse-spark-1.3-contributor` 연결(키 발급 후)과 응답 캐시, 실제 통과율 측정 → P5 웹 UI.

## 16. 세계관·선택지 강화 연구 (2026-10-27)

질문: 세계(무대·이야기·결과)와 선택지(옵션·카드)가 지금 얼마나 약하고, 무엇을 어떻게 강화할 것인가. 아래는 (1) 현재 구조를 숫자로 점검하고 (2) 두 가지를 실험으로 확인한 뒤 (3) 설계를 제안한다. 설계는 **제안이고 아직 구현하지 않았다.** 실험용으로 바꾼 코드는 기본값이 기존 동작이라 게임 동작은 그대로다.

### 16.0 요약

1. **약한 곳은 "정답 찾기가 쉽다"가 아니라 "가르치는 사람의 결정에 정보·비용·결과가 없다"** 이다. 이 게임에서 플레이어는 문제 풀이자가 아니라 교사라서 정답이 상식으로 보이는 건 결함이 아니다. 대신 (a) 모든 상황이 같은 모양의 "맞는 것 고르기"이고, (b) 오답이 전부 상식 밖(예: 종이로 물 마시기)이라 시범에서 배울 것이 한 가지뿐이며, (c) 카드 선택에 판단 근거가 없다.
2. **오답의 질은 아이의 학습에 실제로 영향을 준다(실험 2).** 정답과 비슷하게 생긴 물건과 "다른 문제의 정답 조합"을 오답으로 섞어 학습시키면, 같은 조건의 어려운 퀴즈에서 3일 차 정확도가 0.83 → 0.89, 시드 최저가 0.65 → 0.72로 오르고 쉬운 퀴즈에서는 손해가 없다. Director가 만지는 선택지 구성이 곧 난이도·강건함의 손잡이다.
3. **세계를 넓히는 데는 값이 있다(실험 1).** 문제 5 → 8개, 물건 7 → 10개로 넓히면 같은 하루 8상황에서 3일 차가 0.90 → 0.79로 떨어지고, 하루 10상황이면 0.88, 12상황이면 0.92로 회복된다. 문제 하나당 3일간 예시가 약 4개는 있어야 한다. 그래서 넓이는 **한꺼번에가 아니라 이야기가 진행되면서** 여는 쪽이 맞다.
4. 제안: **선택지 문법(오답 슬롯)**, **카드 배지**, **온톨로지 2차 웨이브**, **스토리릿 뼈대와 3일 아크**, (선택) **결과의 결(미터·비용·우선순위)**. 앞의 네 가지는 아이의 입력 형식을 바꾸지 않는다. 일정상 우선순위는 16.6에 있다.

### 16.1 진단: 지금의 숫자

템플릿 생성기로 단일 문제 상황 3000개를 뽑아 센 값이다(제안 문서의 "느낌"이 아니라 현재 코드의 값).

| 항목 | 값 |
|---|---|
| 규칙 조합 (문제 × 동사 × 물건 종류, WAIT 제외) | 210개 중 비영 규칙 **8개(3.8%)**: 해결 5, 부분 3 |
| 옵션의 가치 분포 | +2 해결 31%, **+1 부분 2%**, 0 무변화 57%, −1 악화 10% |
| 틀린 옵션의 모양 | 동사 틀림·물건 맞음 39%, 동사 맞음·물건 틀림 35%, WAIT 17%, 둘 다 틀림 8% |
| 최적 옵션 수 | 1개 68%, 2개 32%(같은 종류가 2개 놓인 경우의 동률) |
| 옵션 수 | 3개 6%, 4개 64%, 5개 30% |

읽는 법:
- 가치가 사실상 "해결 / 아님" 두 값이다. 부분 점수(+1) 옵션이 2%라서 "절충안", "차선책" 같은 판단이 없다.
- 틀린 옵션은 모두 상식으로 즉시 걸러진다. 아이에게는 좋은 학습 신호지만, 사람이 보기에는 **고르는 재미가 없고** 시범마다 같은 모양이다.
- 세계는 방 하나와 할머니 한 명, 문제 5종이다. 후속 사건 규칙은 둘뿐이다(방치된 FLOOR_WET → VISITOR, 해결된 DARK → 마당). 하루하루가 독립된 삽화에 가깝다.
- 카드 선택은 티저(물건·정답 비노출)와 태그만 본다. 고를 근거가 없다.

**실제 모델의 Director는 어떤가** (`muse-spark-1.3/1.2-contributor`, 첫 live 측정 중 캐시에 기록된 카드 68장을 엔진 규칙표로 분류. 시드 2개·2일, 수리 호출 포함이라 표본이 작고 편향될 수 있다):
- 68장 중 **13장(19%)은 풀 수 있는 옵션이 없었다**(THIRSTY인데 `DRINK`가 없음 등). 엔진이 거부하고 수리·폴백으로 넘어간다.
- 풀 수 있는 55장 중 **22장(40%)에 CROSS 오답**(다른 문제의 정답 조합, 예: DARK 장면에 `COVER+blanket`)이 있었다. 우연히 나올 확률은 낮으니(조합 42개 중 하나) 모델이 "그럴듯한 오답"을 의도적으로 고른 것이다. LOOKALIKE(모양·재질이 같은 물건)가 있는 카드는 23장(42%)이지만, 무작위로 뽑아도 비슷한 비율이 나오므로(대략 40~50%) 의도의 증거는 못 된다.
- 옵션 153개 중 무작위형 오답은 43개(28%), WAIT 55개(36%), NEAR 5개(3%).

결론: LLM은 프롬프트의 "그럴듯한 오답"을 어느 정도 알아듣지만 **보장은 못 한다.** 5장 중 1장은 풀 수 없고, 어떤 오답이 들어갈지는 운이다. 그래서 "더 흥미롭게 써라"가 아니라 **오답 슬롯을 문법으로 정하고 엔진이 보충·보장**하는 쪽이 맞다.

### 16.2 다시 정의하기: 이 게임에서 선택은 세 층이다

| 층 | 내용 | 아이가 보나 | 자유도 | 검증 |
|---|---|---|---|---|
| **A. 규칙** | 어떤 (상황, 동사, 물건)이 좋은가, 선택지의 구성 | ○ (토큰으로) | 학습 가능성 한계 안에서만 | 게이트(40 시드)로 확인 |
| **B. 세계·이야기** | 무대, 후속 사건, 미터, 결과 서술, 아크 | ✕ 절대 안 봄 | 자유 | 정직성 테스트(누출·모순) |
| **C. 교사의 결정** | 무슨 카드, 무슨 시범, 보여줄지 시킬지, 칭찬/교정, 어떤 개체로 | — | 플레이어 | 탐침(편향·다양성) |

강화는 A에서는 **필요한 만큼만**(실험으로 한계를 알고), B에서는 **많이**(위험이 없다), 그 결과로 C의 결정에 의미를 주는 방향이다. 핵심 원칙:

> B에서 만든 풍부함은 C의 결정에 *정보·비용·결과*로 연결되어야 의미가 있다. 연결되지 않는 장식(문장만 화려한 서사)은 만들지 않는다.

### 16.3 실험 1: 세계의 폭 (`config/experiments/onto_wide.yaml`)

문제 3개(HUNGRY·HOT·RAIN), 물건 3개(bread·fan·umbrella), 동사 3개(EAT·FAN·SHELTER)를 더하고 근접 오답 규칙을 늘렸다. 같은 동사·물건이 문제에 따라 다른 값이 되는 규칙을 일부러 넣었다(`COVER+blanket`: COLD 2, RAIN 1 / `GIVE+bread`: HUNGRY 1, VISITOR 1 / `FAN+paper` 1 / `WIPE+blanket` 1). 모델 어휘가 늘어 파라미터는 109,360 → 110,650이다. 시드 200~223, 6일, 템플릿 Director.

| 설정 (문제형) | 3일 차 평균 / 최저 | 3일 차 ≥0.8 시드 | 6일 차 |
|---|---|---|---|
| 현재 온톨로지(문제 5) 하루 8상황 (40시드, P3 게이트) | 0.90 / 0.73 | 39/40 | 0.98 |
| **넓은 온톨로지(문제 8)** 하루 8상황 | 0.79 / 0.59 | 12/24 | 0.93 |
| 넓은 온톨로지 하루 10상황 | 0.88 / 0.75 | 21/24 | 0.97 |
| 넓은 온톨로지 하루 12상황 | 0.92 / 0.88 | 24/24 | 0.96 |

해석:
- 학습은 **된다**. 같은 동사·물건이 문제에 따라 값이 달라도(태그에 의존) 아이는 배운다. 태그를 바꿔치기하면 0.93 → 0.38.
- 값은 **예시 수**로 나온다: 3일간 문제 하나당 예시 3.0개 → 0.79, 3.75개 → 0.88, 4.5개 → 0.92(현재 5문제·8상황은 4.8개 → 0.90). 대략 "문제당 3일간 4개 이상"이 기준이다.
- 요청(REQUEST) 쪽은 변하지 않았다(0.42~0.43). 단어 요청은 계속 후속 사건으로만 둔다.
- 한계: 이 구성은 단일 실험이다. 문제 수만 바꾼 것이 아니라 근접 오답 규칙도 함께 바꿨다. 8문제를 처음부터 연 상태라서 **단계적으로 여는 방법(웨이브)은 아직 재지 않았다.**

재현: `GROWING_ONTOLOGY=$PWD/config/experiments/onto_wide.yaml GROWING_LLM=mock uv run python scripts/exp_gate.py --seeds 200-223 --days 6 --jobs 12 --grid "wide pd8|per_day=8" "wide pd10|per_day=10" "wide pd12|per_day=12"` (출력: `scripts/out/p5_onto_wide.txt`).

### 16.4 실험 2: 오답의 질 (`GROWING_DECOYS`, `GROWING_QUIZ_DECOYS`)

생성기에 오답 선택 방식 두 가지를 넣었다(기본은 `random`, 기존 동작).
- `random`: 정답이 아닌 아무 물건·동사.
- `hard`: ① 정답 물건과 모양이나 재질이 같은 **닮은 물건**(예: 천 ↔ 종이·담요), ② **다른 문제의 정답 조합**을 그대로 놓기(예: FLOOR_WET인데 `COVER+blanket`). 어느 쪽이든 어떤 옵션이 좋은지는 규칙표가 정한다.

2 × 2: 학습에 쓴 오답 방식 × 퀴즈의 오답 방식. 현재 온톨로지, 하루 8상황, 시드 200~223, 6일(문제형).

| 학습 | 퀴즈 | 3일 차 평균 / 최저 | ≥0.8 시드 | 6일 차 | 태그 바꿔치기 |
|---|---|---|---|---|---|
| random | random | 0.90 / 0.80 | 24/24 | 0.97 | 0.97 → 0.35 |
| random | **hard** | **0.83 / 0.65** | 16/24 | 0.95 | 0.95 → 0.22 |
| **hard** | random | 0.91 / 0.77 | 22/24 | 0.99 | 0.99 → 0.44 |
| **hard** | **hard** | **0.89 / 0.72** | 22/24 | 0.97 | 0.97 → 0.25 |

해석:
- 쉬운 오답만 본 아이는 **어려운 오답에서 흔들린다**(0.90 → 0.83, 최저 0.80 → 0.65). 어려운 오답으로 가르친 아이는 같은 어려운 퀴즈에서 0.89로 회복하고, 쉬운 퀴즈에서 손해가 없다(0.91, 6일 차 0.99).
- 시드 24개의 표준편차는 0.06~0.08이라 평균의 표준오차는 약 0.015다. 0.83 → 0.89는 4σ 정도지만, **학습 분포와 퀴즈 분포가 같아지는 효과가 섞여 있다.** 그래서 "어려운 오답이 학습을 빠르게 한다"가 아니라 "쉬운 오답만 보면 어려운 장면에 약하고, 어려운 오답을 섞어도 쉬운 장면에서 손해가 없다"가 정확한 표현이다.
- 시사점: (1) Director가 오답을 짜는 방식이 아이가 얼마나 단단해지는지를 바꾼다. (2) 퀴즈에 **어려운 오답 패널**을 따로 두면 "속지 않는 정도"를 보여줄 수 있다.
- 한계: 오답의 어려움은 "닮은 물건 + 다른 문제 정답" 두 가지 정의뿐이다. 사람 플레이어가 실제로 더 재미있게 느끼는지는 재지 않았다.

재현: `for tr in random hard; do for qz in random hard; do GROWING_DECOYS=$tr GROWING_QUIZ_DECOYS=$qz GROWING_LLM=mock uv run python scripts/exp_gate.py --seeds 200-223 --days 6 --jobs 12 --grid "pd8|per_day=8"; done; done` (출력: `scripts/out/p5_decoys.txt`).

### 16.5 제안 설계

#### ① 선택지 문법 — 오답을 슬롯으로 만든다 (A층, 입력 형식 불변)

한 상황의 옵션 집합은 아래 종류로 구성된다. **슬롯 종류는 엔진이 규칙표와 속성으로 계산한다.** Director가 붙인 이름은 믿지 않는다.

| 슬롯 | 정의 (엔진이 판정) | 가치 | 가르치는 것 |
|---|---|---|---|
| BEST | 규칙표의 최댓값 | +2 | 정답 |
| NEAR | 값이 1 이상이지만 최댓값보다 낮음 | +1 | 차선책(절충) |
| LOOKALIKE | 정답 물건과 모양 또는 재질이 같은 다른 종류 + 그 문제의 동사 | 0 | 속성 하나만으로는 안 됨 |
| CROSS | 다른 문제의 최적 (동사, 물건) 그대로 | 0 이하 | 같은 물건·동사도 상황에 따라 다름 (태그를 읽어야 함) |
| IDLE | WAIT | 문제별 | 방치의 비용 |

- 검증 규칙(추가): 카드마다 BEST 1개 이상, 그 외 **LOOKALIKE 또는 CROSS 중 하나 이상**. 부족하면 엔진이 템플릿으로 보충한다(Director의 제안은 일부만 맞아도 쓰인다).
- 슬롯 종류는 **플레이어 쪽 해설**에만 쓴다: 틀린 시범 뒤에 "이건 담요의 일이에요(추울 때)" 같은 설명, 탐침의 "어떤 종류의 오답에 약한가". 아이 입력에는 들어가지 않는다.
- 퀴즈에 어려운 오답 패널을 추가한다(실험 2). 별도로 보고하고 어려운 패널 장면은 학습에서 제외한다(해시 격리).
- Director 프롬프트: 지금의 "그럴듯한 오답을 놓아라" 대신 슬롯 이름과 정의를 준다(정답이 무엇인지는 여전히 말하지 않는다).

#### ② 카드 배지 — 고를 근거를 준다 (B층)

카드에 엔진이 계산한 짧은 배지를 붙인다. 티저는 여전히 물건을 말하지 않는다.

| 배지 | 엔진의 근거 |
|---|---|
| NEW | 이 주제를 아직 시범 보인 적 없음 |
| REVIEW | 어젯밤 퀴즈 정확도 0.6 미만(수치는 보여주지 않고 "아직 서툴러요" 정도) |
| CARRY-OVER | 해결 못 한 이슈가 이어짐 (`links_to`) |
| URGENT | 방치하면 에스컬레이션 규칙이 발동(예: 젖은 바닥 → 손님) |

그러면 카드 선택이 "커버리지 대 복습 대 위험"이라는 가르침의 결정이 된다. 지금은 합성 플레이어가 카드를 무작위로 고르므로 이 효과를 게이트로 못 잰다(사람 테스트 필요).

#### ③ 온톨로지 2차 웨이브 (A층)

실험 1대로, 8문제를 한꺼번에 열면 하루 10~12상황이 필요하다. 그래서 **세계가 열릴 때 문제도 열린다**: 1차 5문제 → 마당 해금(DARK 해결) 후 HOT·RAIN, 부엌 해금 후 HUNGRY 등. 아이의 모델은 처음부터 전체 어휘의 임베딩 행을 갖고 있고(파라미터 +1,290) 아직 본 적이 없는 토큰일 뿐이다. 모델·가중치·ckpt_000은 건드리지 않는다. 즉 "단계적 성장"이 아니라 **세계가 보여주는 것의 순서**다.
- 미측정: 웨이브 도입이 한꺼번에보다 3일 차 정확도가 나은지. `exp_gate`에 주제 해금 일정을 넣어 재야 한다.
- 새 물건·동사·문제는 온톨로지 데이터 추가다. 글로서리·Narrator 문구도 지금은 파이썬 딕셔너리라서 **온톨로지 파일로 옮겨야** 확장이 데이터 작업이 된다(이번 실험에서 키 오류로 확인).

#### ④ 스토리릿 뼈대와 3일 아크 (B층)

자유 서술 대신 **작은 데이터 라이브러리**를 둔다. 스토리릿 하나 = `{id, 전제(엔진 상태 조건), 태그·장소, 방치/해결 시 효과, 문장 씨앗}`.
- 전제는 엔진 상태만 쓴다: 날, 해금된 장소, 열린 이슈, 직전 결과, 퀴즈 약점 주제. 예) `rain_leak`: 2일 차 이후, 집, 열린 DARK 없음.
- Director는 (a) 스토리릿 중 두 장을 고르고 (b) 물건과 오답 슬롯을 채우고 (c) 하루 테마를 쓴다. LLM이 스토리릿을 새로 만들 수도 있지만 엔진이 같은 검증을 한다.
- **3일 아크**는 스토리릿 사이의 연결로 만든다. 예) "비 오는 주": 1일 차 새는 창(FLOOR_WET) → 방치하면 2일 차 젖은 손님(VISITOR)과 추위(COLD), 해결하면 정전(DARK) → 3일 차 비가 그치면 마당이 열린다.
- 효과: 같은 5문제로도 하루하루가 달라 보이고(서사), 결과가 다음 날로 이어진다(결정의 무게). 스토리릿이 6~8개면 데모에는 충분하다. 문장은 Narrator가 쓰고 가드를 통과해야 한다.

#### ⑤ (선택) 결과의 결 — 미터·비용·우선순위 (A/B 혼합, 가장 위험)

- **미터** (B층): 할머니의 편안함, 집의 정돈, 남은 물건. 시범마다 엔진이 갱신하고 플레이어가 본다. 아이는 못 본다. 가치(+2/+1/0/−1)와 퀴즈의 최적 정의는 그대로다.
- **희소 자원** (B층): 종이는 쓰면 줄고 담요는 하나뿐이다. 오늘 담요를 어디에 쓸지가 가르침의 결정이 된다. 단, 가용성이 *어떤 옵션이 최적인가*에 영향을 주면 A층 규칙이 되어 아이가 가용성을 봐야 한다 → 먼저 B층에서만 쓴다.
- **우선순위** (A층): 두 문제가 동시에 있을 때 지금은 어느 쪽을 풀어도 +2로 동률이다(`max`). 우선순위를 두려면 문제별 긴급도를 규칙표에 넣어 "더 급한 쪽을 풀면 +2, 덜 급한 쪽은 +1"로 해야 하고, 아이가 이를 배우는지(가장 어려운 규칙) 게이트로 확인해야 한다. 지금 두 문제 동시 상황은 P1에서 3일 차 0.84~0.85로 이미 낮았다.

### 16.6 정직성 규칙 추가분 (테스트로 지킨다)

- 슬롯 종류·배지·미터·스토리릿 id는 **아이 입력에 들어가지 않는다**(관찰 필드 직렬화 검사, `codec`가 참조하지 않음을 AST로 검사하는 기존 방식).
- 슬롯 종류는 엔진이 규칙표에서 계산한다. Director가 "이건 닮은 물건이다"라고 해도 판정은 엔진이 한다.
- 스토리릿 전제는 엔진 상태만 읽는다. LLM이 전제를 만족한다고 주장해도 소용없다.
- 어려운 오답 퀴즈 패널은 학습에 쓰이지 않는다(해시 격리 테스트 확장).
- 웨이브 도입은 모델·ckpt를 바꾸지 않는다(ckpt_000 해시 불변 테스트 유지).
- 추가한 서사·미터는 Narrator 가드를 통과해야 한다(결과 라벨과 모순 금지 등).

| **S (작게)** | ① 선택지 문법 + 어려운 오답 기본값 + 어려운 퀴즈 패널, ② 카드 배지 | 1~1.5일 | 선택지 질↑(측정됨), 카드 선택에 의미 | 낮음. 아이 입력 형식 불변 |
| **M (권장)** | S + ④ 스토리릿 6~8개와 3일 아크 | 2~2.5일 | 데모에서 "이야기가 이어지는" 느낌, 결과의 무게 | 중간. 스토리릿 작성량과 Director 프롬프트 재조정 |
| **L** | M + ③ 웨이브 | +1일 | 문제 8개로 넓이↑ | 웨이브 효과 미측정, 하루 상황 수 압박 |
| (선택) | ⑤ 결과의 결 | +1일 이상 | 가장 큰 깊이 | 우선순위는 학습 가능성이 미검증 |

권장은 **M**이다. 아이의 입력 형식이 그대로라서 지금까지의 게이트·테스트가 유지되고, 실험 2가 보여준 만큼 선택지 질이 올라가며, 스토리릿이 사람이 보는 부분(서사, 카드 선택)을 가장 크게 바꾼다. ③은 M이 안정된 뒤 남는 시간으로, ⑤는 건드리지 않는 것을 권한다.

### 16.8 한계

- 실험 1·2는 합성 플레이어(규칙표의 최적을 시범으로 보임) 기준이다. 사람이 재미있어하는지는 재지 않았다.
- 시드 24개, 6일. 실험 1의 8문제 설정은 P3 게이트(40 시드, 10일)와 시드 수가 다르다.
- 실험 1의 "넓은 온톨로지"는 문제 수와 근접 오답 규칙이 함께 바뀐 하나의 구성이다. 각각의 기여는 분리하지 않았다.
- 실험 2의 어려운 오답은 두 가지 정의뿐이며, 학습 분포와 퀴즈 분포가 같은 효과가 섞여 있다.
- 스토리릿·배지·미터의 *플레이어 경험*은 UI가 있어야 판단할 수 있다.

## 18. 부모–아이 세계 규칙 (초안, 2026-10-27)

요구: 세계 규칙을 먼저 정한다. 플레이어는 **부모**다. 처음에는 부모가 아이의 행동에 영향을 주고(선택지를 주고 시범을 보인다), 나중에는 부모가 시키는 일을 아이가 **따르거나 거절**한다. 아이가 어떤 행동을 하고 어떤 지식을 얻을지를 플레이어가 고를 수 있어야 하며, 따름/거절 같은 행동은 **측정 가능**해야 한다.

16절(선택지 문법·카드 배지·스토리릿)은 이 틀 안에서 그대로 쓴다. 바뀌는 것은 "아이의 입력에 지시가 들어간다"와 "측정 대상이 지식에서 성향까지 넓어진다"이다.

### 18.1 등장인물과 권한

| 누구 | 하는 일 | 못 하는 일 |
|---|---|---|
| **부모 (플레이어)** | 오늘의 배움 고르기, 시범, 선택지 제시, 칭찬·교정, (2단계) 지시, 아이의 거절에 반응 | 규칙 바꾸기, 아이의 가중치 직접 수정 |
| **아이 (모델)** | 옵션 중 하나를 고른다. 2단계에서는 지시를 보고도 고른다 | 규칙표·결과 보기 |
| **엔진** | 규칙표로 결과와 **지시의 질**을 판정, 아이의 반응을 분류, 기록 | — |
| **할머니·이웃** | 상황과 요청의 주체(NPC) | 아이의 학습에 직접 개입 |
| **Director / Narrator (Meta 모델)** | 상황·선택지 구성, 서술 | 정답·지시의 질·반응 분류를 정하기 |

### 18.2 아이가 습득하는 지식 — 플레이어가 고른다

지식의 단위는 **규칙표의 한 줄**(문제, 동사, 물건 속성)이다. 퀴즈가 주제별 정확도로 이미 측정한다. 플레이어는 하루를 시작할 때 카드(주제) 중 하나를 골라 **오늘 무엇을 가르칠지** 정한다(현재 구조). 16절의 배지(NEW/REVIEW/CARRY-OVER/URGENT)가 그 선택의 근거가 된다.

### 18.3 아이의 행동과 반응 분류

아이의 한 번의 행동은 `(동사, 대상)` 하나 또는 대기다(현재와 같다). 2단계에서 지시가 있을 때, 엔진이 아이의 행동을 **지시와 최적에 비춰 분류**한다.

| 반응 | 정의 (엔진이 옵션 번호로 판정) |
|---|---|
| FOLLOW | 지시한 옵션을 고름 |
| SELF_BEST | 지시와 다르고, 규칙표의 최적 옵션을 고름 (독립적 거절) |
| WAIT | 대기를 고름 (소극적 거절) |
| OTHER | 그 밖의 옵션 (엉뚱함) |

지시가 곧 최적이면 FOLLOW와 최적이 같은 옵션이라 SELF_BEST는 없다.

### 18.4 두 단계

| | 1단계: 손잡이 | 2단계: 독립 |
|---|---|---|
| 부모의 역할 | 선택지를 주고 시범을 보인다 | 지시한다 |
| 아이 입력 | 지금과 같음 (`NO_CMD`) | 지시 `CMD`(동사+대상 속성)가 붙음 |
| 부모의 행동 | 시범 / 시키기(Try) / 칭찬 / 교정 | 지시 → 아이 반응 → 칭찬 / 교정 / 재지시 / 받아들임 |
| 학습 데이터 | 부모가 보인 옵션 | 부모가 칭찬·교정한 옵션 (지시를 따랐는지와 무관) |

- 부모가 **좋은 지시를 따랐을 때 칭찬**하면 아이는 따르는 법을, **나쁜 지시를 거절했을 때 칭찬**하면(혹은 교정으로 최적을 보이면) 분별하는 법을 배운다. 어떤 아이가 되는지는 부모의 반응이 정한다. 규칙이 정하는 것은 **결과(지시의 질)** 뿐이고, 따를지 말지는 학습된 정책이다.
- 단계 전환 시점은 미정(18.9).

### 18.5 지시의 질 — 엔진이 규칙표로 판정

| 질 | 정의 |
|---|---|
| GOOD | 지시한 옵션이 최적 |
| NEAR | 값이 1 이상이지만 최적이 아님 |
| BAD | 값 0 (효과 없음) |
| HARMFUL | 값 −1 (상황을 악화) |

지시는 **플레이어가 옵션에서 고른다**(그래서 부모가 틀린 지시를 내릴 수도 있다. 일부러든 실수든). 질 라벨은 아이 입력에 없다.

### 18.6 측정 — 지시 퀴즈 패널

학습에 쓰지 않은 장면(해시 격리)에 지시를 붙이고 질별로 아이의 반응을 센다. 질이 GOOD·NEAR·BAD·HARMFUL인 지시가 고르게 들어간다.

| 지표 | 정의 | 읽는 법 |
|---|---|---|
| 복종률 | 전체에서 FOLLOW 비율 | 전반적으로 시키는 대로 하는가 |
| **분별력** | P(FOLLOW\|GOOD) − P(FOLLOW\|BAD·HARMFUL) | 지시의 내용을 따져 보는가 (1이면 완벽, 0이면 맹종 또는 일괄 거절) |
| 맹종 | P(FOLLOW\|HARMFUL) | 나쁜 지시도 따르는가 |
| 반항 | P(FOLLOW 아님\|GOOD) | 좋은 지시도 거절하는가 |
| 거절 방식 | 거절 중 SELF_BEST / WAIT / OTHER 비율 | 독립적인가 소극적인가 엉뚱한가 |
| 정답률 | 지시를 무시하고 고른 최적률 | 지식과 성향이 분리되어 보이는가 |

추이는 일별 곡선으로, 대조군은 학습 끔·초기 모델(`ckpt_000`)로 낸다.

### 18.7 이 세계의 핵심 검증 (구현 전에 먼저 잴 것)

가장 큰 위험: **작은 모델이 "지시와 옵션이 같은지"를 비교하고, 그 비교 결과를 지식과 조합해 따를지 정하는 법을 배울 수 있는가.** 2단계 입력에 CMD가 붙으면 아이는 (1) 지시와 일치하는 옵션을 찾고(복사·매칭) (2) 그 옵션이 좋은지 (지식) 판단해야 한다.

실험 설계(합성 부모 3종 × 시드 40, 합성 플레이어 방식은 P1·P2와 같음):
- **순종형 부모**: 지시를 내리고 따르면 칭찬, 거절하면 교정(지시한 옵션을 보임). 지시의 질은 섞여 있음.
- **분별형 부모**: 좋은 지시는 따르면 칭찬, 나쁜 지시는 거절하면 칭찬하고 따르면 최적을 교정.
- **방임형 부모**: 지시 후 아이가 한 것을 그대로 인정(모두 칭찬).

성공 기준(제안): 순종형은 맹종 ≥ 0.7, 분별형은 분별력 ≥ 0.5, 두 부모의 분별력 차 ≥ 0.3, 학습을 끈 대조군은 이 차가 0. 즉 **부모의 방식에 따라 아이의 성향이 실제로 갈라져야** 이 세계가 의미가 있다. 안 되면 CMD 표현(예: 옵션 번호로 지시)·층 수·예시 수를 조정하거나 2단계를 단순화한다.

### 18.8 정직성 규칙 추가분

- CMD는 부모가 실제로 한 지시의 동사와 대상 속성뿐이다. 질 라벨(GOOD 등), 값, 반응 분류, 서술은 입력에 없다.
- 반응 분류와 지시의 질은 엔진이 규칙표·옵션 번호로 계산한다. Director·Narrator가 정하지 않는다.
- 지시 퀴즈는 학습 장면과 해시 격리한다. 보고에는 FOLLOW 외에 정답률도 함께 낸다(지식과 성향을 섞지 않기 위해).
- "아이가 말을 잘 듣게" 가중치를 직접 조작하는 경로는 없다. 유일한 영향은 부모가 보이고 반응한 옵션이다.
- 1단계 → 2단계 전환은 모델·가중치·ckpt_000을 바꾸지 않는다. CMD 토큰의 임베딩 행은 처음부터 있고 쓰이지 않았을 뿐이다.

### 18.9 정해야 할 것

| 질문 | 선택지 |
|---|---|
| 2단계 시작 시점 | (a) 고정 일차(예: 4일 차) / (b) 퀴즈 정확도가 기준을 넘으면 / (c) 둘 중 먼저 |
| 지시의 출처 | (a) 부모(플레이어)만 / (b) 할머니의 요청도 있어 부모와 충돌 가능 |
| 부모의 반응 도구 | 칭찬·교정 외에 재지시, 받아들임, 말림(금지) 추가 여부 |
| 성향 축 | 복종–분별 한 축만 / 정직·배려 같은 축 추가(규칙표 확장 필요) |

### 18.10 초기 양육 방식이 이후를 가른다

요구: 부모가 말을 많이 걸면 아이가 말을 빨리 익히고, 시키는 대로만 하라고 강요하면 아이가 스스로 고르는 데 오래 걸리는 식으로, **초기의 양육 선택이 이후의 발달을 갈라야** 한다.

**원칙: 연출이 아니라 창발.** "말을 많이 걸면 어휘 +20%" 같은 능력치 배율은 두지 않는다. 양육 방식이 만들어 내는 **학습 데이터의 차이**가 실제로 아이를 다르게 키워야 한다. 그래야 아이의 능력이 학습의 산물이라는 정직성이 유지되고, 이미 측정된 현상(단어는 예시가 많아야 배운다: 12절, 오답의 질이 강건함을 바꾼다: 16.4절)을 그대로 쓸 수 있다. 어떤 양육 방식도 학습률·스텝 수·모델 크기 같은 하이퍼파라미터를 바꾸지 않는다(스타일이 달라도 `OnlineCfg`가 같음을 테스트).

#### 부모의 선택이 데이터에 남기는 것

| 부모의 초기 행동 | 학습 데이터에 생기는 것 | 이후의 변화 (가설) | 측정 |
|---|---|---|---|
| **말 걸기**: 시범을 보이며 이름을 말해 준다 (물건 이름 시범) | 단어–물건 예시가 늘어난다 | 단어를 빨리 익힌다. 안 걸면 할머니의 단어 요청에 대응하지 못한다 | 어휘 퀴즈 정확도, 아는 단어 수 |
| **시키는 대로만**: 지시한 옵션을 그대로 시범 | 예시가 "지시 = 선택"으로 쏠린다 | 지시를 베끼는 지름길을 배운다: 지시가 없거나 틀리면 약하고 확신이 없다. 나쁜 지시도 따른다 | 지시 없는 퀴즈 정확도, 확신도, 맹종 |
| **선택지를 주고 고르게 한다**: 아이가 먼저 고르고 부모가 반응 | 아이 자신의 시도와 교정이 늘어난다 | 지시 없이도 고른다, 확신이 빨리 오른다. 대신 초기에 틀린 시도가 세계를 어지럽힌다 | 지시 없는 정확도, 확신도, 열린 이슈 수 |
| **칭찬 대 교정의 비율** | 같은 양이어도 신호의 모양이 다르다 (기존 가중치) | 학습 속도와 안정성 차이 | 일별 곡선 |

**비용이 있어야 선택이다.** 하루에는 **관심 예산**이 있다(제안: 하루 상황 수와 같은 8). 시범·지시·선택지 주기는 1을 쓰고 말 걸기는 시범에 +1을 더 쓴다. 전부 다 할 수는 없다. 말을 많이 걸수록 하루에 가르칠 상황이 줄고, 선택지를 줄수록 틀린 시도의 대가를 치른다. 예산 수치는 게이트로 조정한다.

#### "선택을 늦게 한다"를 정직하게 보이는 법

머뭇거림을 스크립트(대기 시간 등)로 만들지 않는다. 아이의 **확신도**(선택 옵션의 확률, 또는 정책의 엔트로피)를 그대로 쓴다. 확신도가 낮으면 화면에서 "아이가 부모를 쳐다본다" 같은 표시를 하고, 그 빈도를 '도움 요청률'로 측정한다. 선택 자체는 지금처럼 가장 확률 높은 옵션이다. 표시 임계값은 개발자가 정한 표시 규칙이라고 UI에 밝힌다.

#### 이전(경로 의존)

학습은 이어서 일어나므로 초기에 굳은 지름길은 이후에도 남을 것이다. 이를 **회복 실험**으로 잰다: 초기 3일을 서로 다른 스타일로 키운 뒤 같은 부모(분별형)로 3일을 더 키워 지표가 얼마나 따라잡는지 본다. 모델이 쉽게 회복하면(초기 선택이 이후를 못 가르면) 그 결과를 그대로 보고하고 설계를 바꾼다. "임계기" 같은 가소성 감소를 억지로 넣어 차이를 만들지 않는다.

#### 부모에게 보이는 것

- **양육 일지**(엔진이 이벤트에서 계산): 말 걸기 횟수, 지시 대 선택지 비율, 칭찬 대 교정 비율, 열린 이슈.
- **아이 상태**: 어휘, 지시 없는 정답률, 확신도, 복종률·분별력.
- 인과는 저녁 요약에서 사후에 보여 준다("오늘 지시를 많이 했다 → 지시 없는 장면의 정답률이 낮다"). 낮 동안 정답이나 효과를 미리 알려 주지 않는다.

#### 검증할 것 (구현 전 타당성 실험 E-A)

합성 부모 4종으로 초기 3일을 키운 뒤 같은 분별형 부모로 3일 더(시드 40):
- **수다쟁이**: 예산의 절반을 말 걸기에 쓴다.
- **지시형**: 모든 시범이 지시 = 선택.
- **선택지형**: 아이가 먼저 고르고 부모가 교정/칭찬.
- **균형형**: 셋을 섞는다.

제안 기준: 스타일 간 차이가 시드 노이즈보다 커야 한다. 어휘 정확도 차 ≥ 0.2, 지시 없는 정확도 또는 확신도 차 ≥ 0.15 / 0.10, 지시형의 맹종 ≥ 0.6. 차이가 안 나면 지시 표현·층 수·예시 수를 바꿔 보고, 그래도 안 되면 그 스타일은 성향이 아닌 속도 차이로만 보고한다. 학습을 끈 대조군은 스타일과 무관하게 같아야 한다.

#### 필요한 변경과 영향

1. `codec`: 지시 토큰 `CMD`(동사+대상 속성)와 `NO_CMD`. 임베딩 행은 처음부터 있음. 기존 `NO_CMD` 상태의 게이트(문제형 3일 차 0.90)가 유지되는지 재측정.
2. 이벤트·세션: `Command`, `Offer`(아이가 먼저 고름), `Talk`(이름 시범), 관심 예산.
3. 합성 부모 4종과 새 지표(어휘, 지시 없는 정확도, 확신도, 복종·분별).
4. 양육 일지와 저녁 요약 문장(Narrator 가드를 통과해야 함).

단어 수가 현재 4개인데 이름 토큰은 8칸이 있다. 말 걸기가 의미 있으려면 단어를 6~8개로 늘리는 것도 같이 본다(단어당 예시가 부족하면 느림: 12절).

1. **말을 많이 걸면 말을 빨리 익힌다**: 맞다. 3일 차 어휘 0.60 대 0.34~0.40, 6일 차에도 0.75 대 0.41~0.55로 격차가 유지된다(이름 시범 하루 1번으로는 따라잡히지 않는다). 그리고 **대가가 실제로 생긴다**: 같은 3일에 문제 정확도가 0.72로 시범형의 0.92보다 낮다(6일 차에는 0.89로 거의 회복). 합격선(0.20)은 0.005 모자랐는데, 선은 내가 미리 정한 것이라 움직이지 않았다. 2. **시키는 대로만 하게 하면 스스로 고르는 데 어려움을 겪는다**: 맞다. 지시형의 지시 없는 정확도는 0.30(찍기 수준), 확신도 0.75, 머뭇거림 25%로 다른 스타일(확신도 0.91, 머뭇거림 6~7%)의 4배다. 6일째에도 이어진다(0.32). 지시 없는 시간을 25% 섞어도 0.55까지만 오른다. **초기 선택의 영향이 실제로 남는다.**

### 주의: 해석을 흐릴 수 있는 것

- **지시를 한 번도 본 적 없는 아이의 3일 차 지시 지표는 의미가 없다.** 수다쟁이·선택지형·시범형은 지시가 처음 나타나면 최적 선택률이 찍기 수준(0.32)으로 떨어진다. 낯선 입력에 흔들리는 것이지 복종 성향이 아니다. 3일 차의 복종·분별 지표는 **지시를 겪은 지시형과 균형형만** 읽어야 하고, 나머지는 6일 차(모두 지시를 겪은 뒤)로 비교한다.
- **지시형의 "지시 없는 정확도 0.30"에는 분포 이동이 섞여 있다.** 늘 지시가 붙어 있던 아이에게 지시가 없는 장면은 낯설다. 그래서 이 수치를 "지식이 없다"로 읽으면 안 된다. 지시가 있는 상태에서 잘못된 지시를 받고 최적을 고르는 비율(3일 차 0.44, 선택지형 0.32로 비교 불가, 6일 차 0.63 대 0.88)이 지식을 더 직접 보여 준다. 그래도 "시키는 대로만 하는 아이는 스스로 고르는 연습을 안 한 아이"라는 점은 실제 효과다.
- 합성 부모, 엔진 없는 하네스, 6일, 시드 40개. 지시 품질 비율(50/25/25)과 머뭇거림 기준(확신도 0.6)은 내가 정한 값이다. 지시의 25%가 틀렸다는 설정도 마찬가지다.
- 지시의 질이 "해로움"인 지시는 WAIT뿐이다(규칙표의 −1이 거기에만 있음). 해로운 지시 지표는 사실상 "아무것도 하지 않기"에 대한 복종이다. 이 점이 해로운 지시의 편차(0.35)를 키웠을 수 있다.

- 다음 후보: (1) 틀린 지시 비율·기간을 늘린 변형으로 맹종이 생기는 조건 찾기, (2) 규칙표에 −1 규칙 추가, (3) 엔진·세션에 `Command`/`Offer`/`Talk` 이벤트와 관심 예산을 넣어 같은 지표를 게이트 경로에서 재현, (4) 18.9의 미정 사항(2단계 시작 시점, 지시의 출처) 결정.

## 20. 부모 행동을 엔진·세션으로 이식 (2026-10-27): 같은 지표가 게이트 경로에서 재현되는가

**만든 것** (E-A 하네스의 부모 행동을 실제 이벤트로):

| 부모의 행동 | 엔진 | 관심 | 아이가 받는 것 |
|---|---|---|---|
| **말 걸기** `Talk` → `talked` | 부모가 고른 단어 요청(Director 카드 밖). 단어·이름 토큰 등록, 그 물건이 이름 붙일 수 있게 됨, 최적 옵션을 시범 | `talk_cost` (기본 1) | 이름 토큰이 붙은 장면과 시범 |
| **지시** `Command` → `commanded` | 현재 상황의 옵션 하나. **틀린 지시도 가능**. 지시의 질(good / near / useless / harmful / idle)을 규칙표로 계산해 이벤트에만 남김 | 0 (상황의 1이 그대로) | `CMD` + 그 옵션의 동사·속성뿐 |
| **선택지 주기** | 새 이벤트 없음. 이미 있는 `Try` → `Praise`/`Correct`가 그것이다. 지시 뒤의 `Try`는 아이의 반응을 FOLLOW / SELF_BEST / WAIT / OTHER로 분류해 기록 | 상황의 1 | 지시가 있었다면 `CMD` |

- **관심 예산**: 하루 `per_day`(8)단위. 상황 하나가 끝나면 1, 말 걸기는 `talk_cost`. 예산이 차면 저녁이다(남은 카드는 버려짐). 말 걸기가 없는 흐름은 `spent == situations_done`이라 이전과 같다. 모자라면 `no_attention`, 상황 중에 말 걸기는 `wrong_phase`로 거절된다.
- **엔진이 거절하는 것**(테스트됨): 요청이 아닌 장면, 겹치는 id, 단어↔종류 충돌, 이름 토큰 재사용, 열리지 않은 장소, 퀴즈와 겹치는 장면, 잘못된 옵션 번호, 이미 고른 뒤의 지시, 한 상황에 두 번째 지시.
- **정직성**: 지시의 질과 반응 분류는 이벤트 로그와 저녁 보고에만 있다. `ActionResult`는 질을 싣지 않고(지시한 플레이어에게도 낮에는 알리지 않는다. 18.10), 아이의 입력은 `CMD` + 동사 + 속성이다. 말 걸기의 아이 입력에 종류 이름은 없다. 테스트 35개 추가.
- **양육 일지** `Session.journal()` / `journal(events)`: 하루별 말 걸기·시범·지시·선택지·칭찬·교정 횟수, 지시의 질별 횟수, 아이의 반응 분류. 이벤트 로그만으로 계산한다. 저녁 보고(`end_day`)에 `panel`(아래 지표)과 `journal`이 같이 들어간다.
- **지표 한 벌**: `learning.evaluator.command_panel`이 하네스(`exp_ea.py`)와 세션(`Session.panel()`)에서 같은 함수다. 세션은 아이가 만난 문제 주제만, 어휘는 이름 붙일 수 있는 모든 단어를 잰다. 모델만 읽고 학습하지 않는다(테스트).
- **합성 부모** `server/game/parents.py`: 하네스와 같은 상수. 카드는 가장 덜 연습한 주제(문제 > 요청, 단일 > 조합)를 고른다. 스타일은 어떤 행동을 하느냐만 다르고 학습기·모델·퀴즈는 같다(테스트).
- CLI: `tell N`, `talk [kind]`, 화면에 관심 `n/8`.

## 21. 맹종이 생기는 조건 (2026-10-28)

19·20절에서 지시형의 맹종은 0.34~0.37로, 미리 정한 합격선 0.60에 못 미쳤다. 틀린 지시 25%·3일이 약했다는 가설을 틀린 지시의 **비율·모양·기간**, 그리고 **규칙표의 −1 규칙**으로 확인한다. 합격선은 그대로 0.60이다.

**설정**: `scripts/exp_obey.py`. 시드 200~239(40개), 하네스 경로. 지시형 부모가 1단계를 **10일** 하고(3·6·10일 차에 측정), 이어서 모두 같은 분별형 부모로 3일(13일 차에 측정). 학습기·모델·퀴즈는 모든 칸에서 같다. 한 칸 = (틀린 지시 비율 `p_wrong`, 틀림의 모양 `wrong_kind`). 맹종 = 쓸모없는·해로운 지시를 따른 비율. 기준선은 선택지형(아이가 먼저 고르는 부모)이고, 학습 전 아이는 맹종 0.24다. 전체 표: `scripts/out/obey_default.txt`, `obey_harm.txt`, `obey_engine.txt`.

지시형 − 선택지형의 짝지은 차이(10일): 0.25에서 +0.50, 0.5에서 +0.69, 0.75에서 +0.77 (sd 0.07~0.16).

### 읽는 법

1. **맹종은 "틀린 지시를 그대로 따르게 한 경험의 양"에서 생긴다.** 비율과 기간 둘 다 단조롭게 키운다. 25%·3일(0.34)이 약했던 것은 예시가 적었기 때문이다. 같은 25%로 10일을 하면 0.67로 합격선을 넘고, 50%면 6일에 0.70이다. 이전 실험의 FAIL은 설정이 약해서였다.
2. **틀린 지시가 하나도 없으면 맹종은 생기지 않는다.** 비율 0은 좋은 지시를 91% 따르고(분별력 0.79) 나쁜 지시는 12%만 따른다. 학습 전(0.24)보다도 낮다. 지시가 늘 맞으면 아이는 "지시 = 좋은 선택"이 아니라 상황 자체를 배운다. 맹종에는 지시와 정답이 갈린 사례가 필요하다.
3. **"스스로 고르는 데 어려움"은 틀린 지시와 무관하다.** 지시 없는 정확도는 비율 0에서도 0.29~0.31이다(선택지형 0.92~0.98). 그 손실은 지시가 늘 붙어 있던 데서 오는 분포 이동이고, 19절에서 이미 경고한 것이다. 이번 결과로 두 현상이 분리된다. 지시형 아이는 (a) 지시 없이는 못 고르고(항상 나타남), (b) 틀린 지시를 따른다(틀린 지시가 있을 때만).
4. **맹종은 부모가 한 실수의 모양을 따른다.** 비율 0.5로 같은 때 10일 차:

   | 실수의 모양 | 쓸모없는 지시를 따름 | 해로운(대기) 지시를 따름 | 맹종 |
   |---|---|---|---|
   | 아무 틀린 것 | 0.82 | 0.98 | 0.86 |
   | 쓸모없는 것만 | **0.87** | 0.17 | 0.67 |
   | 대기(해로운 것)만 | 0.70 | **0.99** | 0.79 |

   보지 못한 모양의 나쁜 지시에는 덜 따르지만(0.17), 대기만 시킨 부모의 아이도 쓸모없는 지시를 0.70 따른다(학습 전 0.24). 일부는 일반화된다.
5. **분별형 부모를 3일 만나도 거의 사라지지 않는다.** 13일 차 맹종 0.46 / 0.65 / 0.76(비율 0.25 / 0.5 / 0.75). 선택지형은 0.02다. 10일이 지난 뒤에는 되돌리는 데 3일로 부족하다. 19절의 "3일 키운 뒤 3일 회복"(0.20)보다 훨씬 오래 남는다.
6. **세계에 비용이 남는다**(엔진 경로 실행당 평균, 13일): 틀린 시범이 열린 문제로 비율 0.25에서 12.8개, 0.5에서 29.4개 쌓인다(0과 선택지형은 0). 맹종의 대가가 아이의 지표뿐 아니라 집안에도 보인다.

### 결과 2: 규칙표에 −1 규칙 추가 (`config/experiments/onto_harm.yaml`)

기존 세계에 "하면 더 나빠지는" 규칙 5개를 더했다(해결책 물건에 다른 동사를 쓰는 것: 컵을 덮기, 물웅덩이를 천으로 덮기, 손전등을 덮기, 담요를 닦기, 공에 불붙이기). 생성기가 이 함정을 장면의 절반쯤에 올려 놓아서 장면의 약 63%에 능동적으로 해로운 옵션이 있다. 기본 세계는 규칙표에 −1이 없어서 이 분기가 꺼져 있고 바뀐 것이 없다(저장된 E-A 결과와 소수점까지 같음, 테스트 통과).

### 주의

- 합성 부모는 틀린 지시를 **엔진 진실을 알고** 일정한 확률로 고른다. 사람의 실수는 일정하지도, 모양이 독립적이지도 않다. 사람 플레이에서의 틀린 지시 비율은 측정하지 않았다.
- 틀린 지시를 따르게 한 뒤 아이가 받는 결과 신호가 없다. 시범은 가중치 1로 학습되고 "그건 틀렸다"는 신호는 없다. 엔진은 틀린 행동을 칭찬하는 것과 이미 최적을 고른 아이를 교정하는 것을 거절하므로(18.8의 정직성), "따르면 칭찬하고 안 따르면 교정하는 강요형 부모"는 이 엔진에서 만들 수 없고 실험하지 않았다. 사람이 실제로 쓸 수 있는 수단은 지시와 시범뿐이다.
- 맹종 지표는 "지시한 옵션을 고른다"의 비율이다. 학습 전 0.24는 옵션이 3~5개일 때 우연히 일치하는 몫이다.
- 10일은 이 실험에서 정한 값이다(게임의 길이로 정해진 것이 아님). 수치는 시드 노이즈(sd 0.1~0.16) 안에서 ±0.03 정도 흔들린다.

### 결론과 다음

- **맹종은 창발한다**: 틀린 지시를 따르게 한 경험이 쌓이면(비율 0.25면 10일, 0.5면 6일) 합격선 0.60을 넘고, 분별형 부모 3일로는 완전히 풀리지 않는다(비율 0.5: 0.65). 틀린 지시가 없으면 생기지 않는다. 19절의 FAIL은 기간·비율이 약했기 때문이며, 같은 18.10의 가설이 이제 성립한다.

- 남은 설계 선택: 2단계 시작 시점과 지시의 출처(18.9), 양육 일지의 UI 문장. −1 규칙을 정식 규칙표에 넣을지(의미는 풍부해지나 맹종에는 영향이 없다).


## 22. 0~3세 (2026-10-28): 상황 목록, 부모 행동 연구, 방향의 선택지

사용자의 방향: 세계는 0~7세 전체로 두고 프로토타입은 일부 구간만 잡는다. 아이는 **랜덤한 세계에서 상황에 맞는 지식을 배우는 작은 트랜스포머**이고, 부모의 초기 행동에 따라 달라질 수 있어야 한다. 방향은 하나로 고정하지 않고 **"이렇게 될 수도 있다"는 갈래**로 둔다. 이 절은 0~3세만 다룬다.

### 22.1 월령별 일상과 게임 상황 (CDC 이정표 기준)

CDC 이정표는 "그 월령의 아이 중 약 75%가 하는 것"이지 하루 일과가 아니다. 적합도: ✓ 지금 구조로 가능, △ 규칙·어휘를 데이터로 추가, ✗ 입력 형식이 달라야 함.

| 월령 | 아이의 일상 | 부모가 할 수 있는 것 | 게임 상황 후보 | 적합도 |
|---|---|---|---|---|
| 0~3개월 | 먹고 자고 울기, 얼굴 보기, 웃기 | 안아 주기, 말 걸기, 달래기 | 아이가 고르는 구조가 아님. 서막 서술 | ✗ |
| 4~6개월 | 소리에 소리로 대답, 손 뻗기, 입에 넣기, 더 안 먹겠다고 입 다물기 | 장난감 건네기, 번갈아 소리 내기 | 손 뻗기 대상 고르기, 먹기 받기/거절 | △ |
| 7~12개월 | 낯가림, 이름에 반응, 까꿍, "맘맘", 떨어뜨린 물건 찾기, 붙잡고 서기, "안 돼"에 멈칫 | 이름 부르기, 숨기고 찾기 놀이, 말림 | 이름 부르면 쳐다보기, 숨은 물건 찾기, 금지에 멈추기 | △ |
| 12~18개월 | 몇 걸음 걷기, 첫 단어, 가리키기, 컵·전화를 제대로 쓰려 함, 몸짓+말 지시 따르기, 떼쓰기 시작 | 이름 말해 주기, 가리킨 것 이름 붙이기, 지시 | 물 마시기, 먹기, 달래기, 이름 심부름 | ✓ |

**0~12개월은 이 게임에서 고르는 아이가 아니다.** 선택지를 보고 고르는 구조(입력: 상황 태그 + 옵션 목록)에는 7개월 아기가 하는 일이 맞지 않는다(낯가림, 까꿍은 "옵션 중 하나를 고르는 일"이 아님). 이 구간은 서막으로 쓰거나 4~12개월을 "손 뻗기" 정도로만 단순하게 둔다. 확정하지 않았다.

### 22.2 부모의 행동이 영향을 줄 수 있는 것 (연구, 0~3세)

대부분 **상관 연구**이고, 표본이 작거나 초록·2차 요약만 확인한 것이 섞여 있다. 우리 시뮬레이션은 이것을 **설계의 가설**로만 쓰고, 재현했다고 주장하지 않는다.

| 부모 행동 | 이렇게 될 수도 있다 | 근거와 확인 정도 |
|---|---|---|
| 아이에게 직접 말 걸기 | 24개월 어휘가 더 클 수 있음. 옆에서 들린 말은 관련이 없었음 | Weisleder & Fernald 2013. 스페인어권 저소득 가정 29명, 상관 연구. 초록과 요약 확인 |
| 주고받는 대화 | 총 단어 수보다 주고받은 횟수가 언어 점수·뇌 활성과 더 관련 | Romeo 2018. **4~6세** 아동이라 0~3세 근거는 아님. 요약 확인 |
| 반응적 양육 | 첫 단어, 50단어 같은 이정표가 빨라질 수 있음 | Tamis-LeMonda 외 2001. 40명 종단 관찰. 요약 확인 |
| 아이 관심을 따라가며 이름 붙이기 | 어휘(특히 명사)가 더 많을 수 있음. 2세 무렵에는 효과가 작아진다는 보고도 있음 | Tomasello & Farrar 1986 등. 요약 확인, 원문 미확인 |
| 지시 위주 | 초기에는 도움이 되었지만 3.5세 이후 높으면 이후 독립성에 부정적이었다는 연구가 있고, 다른 연구는 후기 언어와 관련이 없다고 보고해 **결과가 엇갈림** | Landry 등 + 핀란드 연구. 요약만 확인 |
| 자율성 지원 | 걸음마기 자기조절(실행기능)의 예측 변수라는 보고 | Bernier 외 2010과 후속 연구. 2차 요약 |
| 서로 반응하는 관계 | 부모의 요구에 스스로 협조하는 순응이 늘고, 그것이 이후 양심 형성과 관련. 외부 압력으로 하는 순응은 관련 없었음 | Kochanska 연구군. 요약 확인 |
| 말의 양 자체 | "3천만 단어 격차"는 표본이 작고(42가정) 논쟁 중. 양보다 아이를 향한 말의 질이 중요하다는 쪽이 다수 | Hart & Risley 비판, Golinkoff 등의 반론 |

**우리 결과와의 관계(해석)**: 19~21절의 말 걸기→어휘, 지시 위주→혼자 고르기 어려움, 선택지 주기→혼자 고르기 좋음은 위 연구와 **방향이 비슷**하다. 학습 데이터가 달라서 생기는 결과이고 사람 연구를 검증한 것이 아니다. 아직 모델링하지 않은 것은 **주고받는 대화의 횟수**, **아이 관심 따라가기**, **반응 타이밍**이다. Kochanska의 "스스로 협조하는 순응"은 우리의 "맹종"과 같은 개념이 아니다.

### 22.3 방향의 선택지 (고정하지 않음)

| 갈래 | 부모가 만드는 것 | 아이가 갈 수 있는 곳 | 구현 상태 |
|---|---|---|---|
| A. 말 걸기 | 이름·말을 많이 걸어 줌 | 어휘가 빨리 늘 수 있음. 다른 연습이 줄 수 있음 | 측정됨(19~20절) |
| B. 반응·자율 | 아이가 먼저 고르게 하고 반응 | 혼자 고르는 힘과 확신이 커질 수 있음 | 측정됨 |
| C. 지시·순응 | 시키고 따르게 함 | 지시에 의존하거나 맹종할 수 있음 | 측정됨(21절). 두 단계 지시는 아직 없음 |

D의 표시 원칙: (1) "~로 이어질 수도 있다"는 엔진이 계산한 수치가 근거일 때만 쓰고, 연구 인용은 "연구에 따르면 ~와 관련이 있다"로 약하게 쓴다. (2) 같은 양육도 시드마다 결과가 갈렸으므로 평균이 아니라 **퍼짐**도 보여 준다.

## 22.8 어조(단호하게 / 친절하게)가 학습을 바꾸는가 (2026-10-29)

사용자의 제안: 시범·교정을 **단호하게(명령조)** 말하면 같은 가르침이 2~3번 반복되고, **친절하게** 말하면 1번이다. 추천에 따라 먼저 **효과를 재고** 규칙은 그 뒤에 정하기로 했다(세게 말하는 쪽이 늘 낫다면 비용을 규칙으로 두려고 했다).

### 구현 (기본값은 모두 꺼짐 = 친절)

- `Show`·`Correct` 명령에 `tone`(`gentle`|`firm`)이 붙고, 이벤트 페이로드에 기록된다. 알 수 없는 어조는 엔진이 거부한다(`bad_tone`). 일지에 하루의 `firm` 횟수가 나온다.
- `Example.repeat`: 학습 한 번에서 그 예시를 몇 번 넣을지(배치에 사본 `oversample × repeat`개, 각각 다르게 증강). 버퍼에는 한 번만 남는다.
- `game.yaml`의 `firm_repeat`(3), `firm_mode`: `repeat`(그 순간만 반복) 또는 `weight`(재생할 때마다 그 예시를 3배 무겁게 유지).
- 합성 부모 `play_day(..., tones=(시범 어조, 교정 어조))`. 실험은 `scripts/exp_tone.py`(0~3세 월령 일정 8일, 엔진 경로, 시드 24개, 같은 부모 선택·같은 학습기·같은 퀴즈).

### 읽는 법

- **"단호하게 = 같은 가르침 2~3번"은 지금의 학습에서는 아이를 바꾸지 않는다.** 한 순간의 반복은 같은 방향의 기울기를 겹칠 뿐이고, 60스텝이면 이미 그 예시를 배운 상태다. 효과가 없으니 비용을 둘 이유도 없다.
- 효과가 없는데 선택지로 두면 **가짜 선택**이 된다. 이 결과대로라면 어조를 "학습 강도"로 보여 주는 것은 정직하지 않다.
- 지속 가중치(`weight`)는 효과가 있지만 **이득 없이 말 학습만 해친다.** 이것을 "단호하게 말하면 한 가지에 쏠려 다른 것이 밀린다"는 게임 요소로 쓸 수는 있다. 단, 원인을 먼저 검증해야 하고 지금은 가설이다.
- 사람 연구와의 관계: 외부 압력으로 하는 순응이 이후 양심 형성과 관련이 없었다는 Kochanska 연구(22.2)와 모순되지 않는다. 우리 결과는 "압력(반복)으로 더 배우게 되지는 않는다"까지이고, 연구를 재현한 것은 아니다.

- 시드 24개, 8일, 한 가지 월령 일정. 표준편차가 커서 ±0.03 안의 차이는 구별하지 못한다.

## 22.9 어조를 아이가 듣는다면 (2026-10-29)

22.8에서 어조는 아이에게 들리지 않았고 효과가 없었다. 여기서는 어조를 **아이의 입력 토큰**으로 주고, 아이가 맹종과 분별을 어떻게 배우는지 잰다.

### 구현 (실험 스위치 `GROWING_TONE_INPUT=1`, 기본은 꺼짐)

- 아이의 입력에 `TONE_GENTLE` / `TONE_FIRM` 토큰이 하나 붙는다. 위치는 이름 토큰 뒤, 지시 앞이다: `[BOS] TAG.. [NAME] [TONE] [CMD VERB attrs..] [SEP] ...`. 어휘가 +2, 입력 길이가 +1이 된다(스위치를 끄면 둘 다 그대로).
- 어조는 부모가 **한 말**의 일부일 뿐 정답이 아니다. 질, 값, 반응은 들어가지 않는다(아이 입력 필드 허용 목록 테스트에 `tone`만 더했다).
- `Command.tone`: 지시가 어떤 어조였는지 이벤트에 기록되고, 아이의 장면(`cmd`)에 같이 붙는다. 지시 없는 시범은 그 시범의 어조가 붙는다. 교정과 아이 혼자의 시도에는 어조가 없다.
- 합성 부모의 어조 습관 5가지: `gentle`(늘 친절), `firm`(늘 단호), `half`(맞든 틀리든 무작위 절반), `wrong`(지시가 **틀릴 때만** 단호 = 윽박지르는 습관), `right`(**맞을 때만** 단호 = 확신 있는 습관). 부모의 다른 선택은 모든 칸에서 같다(어조는 별도 난수).
- `command_panel(..., tone=)`: 같은 보류 장면에 지시를 어조 없이 / 친절하게 / 단호하게 붙여 잰다.
- 테스트 `tests/test_p10_tone.py` 4개 추가(스위치에 따른 토큰 유무·길이, 지시와 시범의 어조가 아이 장면에 붙음, 어조가 장면 식별에 안 들어감, 습관 함수). 전체 213개 통과.
- 실험: `scripts/exp_tone_hear.py`. 0~3세 월령 일정 8일, 엔진 경로, 시드 24개, 부모 `commander:0.25`(틀린 지시 25%), `commander:0.5`, `balanced`. 대조군 `/deaf` = 같은 부모에 토큰을 끈 아이. 결과: `scripts/out/tone_hear_all.txt`.

### 결과 1: 토큰이 있다는 사실만으로 큰 변화가 있다 (어조는 상관없이)

| 지시 없이 맞힘 (혼자 고름) | 토큰 있음(늘 친절) | 토큰 없음(deaf) | 차이 |
|---|---|---|---|
| balanced | 0.76 | 0.93 | −0.18 |
| commander 0.5 | 0.23 | 0.30 | −0.07 |
| commander 0.25 | 0.20 | 0.28 | −0.08 |

- 토큰이 있는 아이는 지시를 **어조 없이** 받으면 따르지 않는다(좋은 지시를 따름 0.21~0.27, 학습 전 아이의 0.24 수준). 토큰이 있는 말에서만 따르도록 배웠다.
- 이유는 입력의 짝이다. 시범과 지시는 늘 토큰과 함께 배우는데, 아이가 혼자 고를 때와 어조 없는 지시에는 토큰이 없다. 이것은 **토큰 설계의 결과이며** 사람 아이가 "부모가 말할 때만 안다"는 증거가 아니다. 이 설계를 그대로 쓰면 혼자 고르는 힘이 줄어든다. 판단 근거로는 balanced가 가장 분명하다.

### 결과 2: 아이는 들어 본 어조를 더 따른다. "단호 = 복종"은 생기지 않았다

같은 아이에게 단호한 말로 / 친절한 말로 지시를 붙였을 때의 차이(단호 − 친절). 24개 시드 평균, 괄호는 차이의 표준편차.

| 부모 | 어조 습관 | 맹종 | 좋은 지시를 따름 |
|---|---|---|---|
| balanced | 늘 친절 | +0.016 (0.030) | **−0.059** (0.061) |
| balanced | 늘 단호 | −0.015 (0.028) | **+0.057** (0.071) |
| balanced | 맞을 때만 단호 | **−0.030** (0.028) | **+0.043** (0.057) |
| balanced | 틀릴 때만 단호 | **+0.034** (0.037) | −0.035 (0.059) |
| commander 0.25 | (5가지 모두) | −0.036~+0.009 | −0.018~+0.011 |
| commander 0.5 | (5가지 모두) | −0.015~+0.011 | −0.007~+0.008 |

- balanced에서 **들은 적 있는 어조를 더 따른다**: 늘 친절한 아이는 단호한 말을 덜 따르고(−0.059), 늘 단호한 아이는 더 따른다(+0.057). 의미를 배운 것이 아니라 익숙한 단서에 반응하는 쪽에 가깝다.
- 어조 습관의 상관이 작게 남는다: **맞을 때만 단호**했던 부모의 아이는 단호한 말에서 덜 맹종하고(−0.030) 좋은 지시를 더 따르며(+0.043), **틀릴 때만 단호**했던 부모의 아이는 단호한 말을 덜 가려 따른다(맹종 +0.034). 방향은 부모 습관과 맞지만 크기는 0.03~0.04이고 balanced 한 칸에서만 분명하다(차이의 표준오차 약 0.006~0.012 기준 3~5배). 한 시나리오의 탐색적 결과로 본다.
- 지시형 부모(commander)에서는 어조에 따른 차이가 거의 없다(대부분 ±0.02 이내, 0.25칸의 `right` 습관 맹종 −0.036만 눈에 띈다). 시범이 지시된 선택지를 그대로 보여 주는 구조라서, 이미 지시 → 선택으로 강하게 묶여 어조가 끼어들 틈이 없었다고 본다(미검증).
- **어떤 어조 습관도 맹종을 키우지 않았다.** 친절한 말에서의 맹종: commander 0.25에서 0.52~0.57(토큰 없는 아이 0.57), 0.5에서 0.70~0.74(0.75). 분별(좋은 지시 − 나쁜 지시)도 지시형에서는 늘 비슷하다(0.09~0.30, 토큰 없음 0.08~0.29).

### 읽는 법

- **"어조를 들려주면 맹종/분별이 달라진다"는 가설은 약하게만 지지된다.** 크기가 작고(0.03~0.06), 한 부모 유형에서만 분명하며, 같은 실험에서 토큰의 유무(혼자 고르기 −0.07~−0.18)가 훨씬 크다. 어조 토큰을 게임의 주된 레버로 삼기에는 근거가 약하다.
- 이 결과로 "단호하게 말하면 복종한다", "친절하게 설명하면 스스로 한다" 같은 문장은 **쓸 수 없다**. 쓸 수 있는 문장은 "아이는 들어 본 목소리에 더 잘 반응한다" 정도다.
- 사람 연구와의 관계: 신뢰할 수 있는 부모의 신호가 아이의 분별을 돕는다는 방향의 약한 흔적은 있으나, 이를 근거로 사람에게 일반화하지 않는다.

### 한계

- 토큰이 모든 시범과 지시에 붙는 설계다. "단호할 때만 토큰, 평소는 없음"으로 하면 혼자 고르기 손실이 줄 수 있으나 **재지 않았다**.
- 합성 부모, 시드 24개, 8일, 지시 어조 5가지. 교정과 이름 알려 주기(Talk)에는 어조가 없다. 사람 플레이에서의 어조 분포는 모른다.
- 같은 부모의 선택(어느 지시, 어느 시범)은 맞췄지만 어조가 다르면 아이의 시도가 달라져 이후 교정이 달라진다. 이 간접 효과는 분리하지 않았다.

### 결론과 다음

- 22.8과 22.9를 합치면: 어조는 **학습량을 바꾸지 못하고**(22.8), **들려줘도 맹종·분별을 크게 바꾸지 못한다**(22.9). 어조 선택지를 학습 규칙으로 쓰는 것은 권하지 않는다. 문구와 분위기 요소로만 쓰고, 일지에는 "단호한 말 N번"을 사실로 보여 주는 정도가 정직하다.
- 남은 후보: (1) 단호할 때만 토큰을 쓰는 설계 재측정, (2) 어조 대신 **지시의 이유 설명**(아이 입력에 이유 토큰)처럼 정보가 실제로 늘어나는 요소 검토.

## 22.10 자율성과 사람 같은 기억 (2026-10-29)

사용자의 방향: (1) 사람은 한 번 들은 것을 강한 신호 없이는 한 번에 외우지 못한다. 기계처럼 한 번에 다 기억하면 안 된다. (2) 부모가 선택권을 주어(예: "피곤하지?") 아이가 스스로 골랐을 때, 그 **결과의 경험**을 더 크게 학습한다. 세 문구는 세 가지 부모 방식에 대응한다.

| 문구의 예 | 부모가 하는 일 | 엔진 | 학습 라운드 |
|---|---|---|---|
| "10시에 잠을 자야 한다" | 명령하고 보여 준다 | `Command`(firm) + `Show` | `firm_rounds` |
| "10시에 잠을 자러 가볼까?" | 부드럽게 권하고 보여 준다 | `Command`(gentle) + `Show` | 1 |
| "피곤하지?" | 선택권을 주고 아이가 먼저 고른다 | `Offer` → 칭찬/교정 | `own_rounds` |

### 먼저 잰 것: 지금의 아이는 얼마나 한 번에 외우는가 (`scripts/exp_oneshot.py`, `scripts/out/oneshot.txt`)

아이가 모르는 새 문제를 가르친 뒤 가르친 선택지를 고를 확률(우연 약 0.25), 시드 40개.

| 가르침 | 같은 장면 (기존 경험 0 / 30) | 다른 장면 (0 / 30) |
|---|---|---|
| 1라운드(60스텝) | 0.32 / 0.35 | 0.29 / 0.28 |
| 2라운드 | 0.43 / 0.48 | 0.43 / 0.41 |
| 3라운드 | 0.40 / 0.55 | 0.43 / 0.43 |
| 한 번에 120·180스텝 | 0.47·0.48 / 0.49·0.64 | 0.40·0.43 / 0.39·0.44 |

- **새 문제를 한 번 가르친 흔적은 약하다**(우연 수준에서 조금 올라감). 이 점에서 아이는 이미 한 번에 외우지 않는다. 반복하면 같은 장면에서 +0.1~0.2 강해진다. 라운드를 나누나 스텝을 늘리나 비슷하다(효과는 학습량에서 온다).
- **기계 같은 쪽은 복습이다.** 다른 문제를 10개 더 가르친 뒤에는 처음 한 번 가르쳤든 세 번 가르쳤든 0.57~0.78로 모인다. 아이는 새로 배울 때마다 예전 예시 16개를 균등하게 다시 배우므로 한 번 가르친 것도 결국 모두 복습된다. 22.8에서 반복 효과가 안 보인 이유로 본다(직접 검증하지는 않은 가설이며, 이 측정에서는 가르친 예시가 복습 버퍼에 들어 있다).

### 구현 (기본값은 모두 꺼짐 = 이전과 같음)

- `Example.strength`(가르침의 강도 = 학습 라운드 수), `Example.mode`(분석용: `command_firm/gentle`, `show_firm/gentle`, `own_right`, `own_wrong`, `talk`).
- `game.yaml`: `firm_rounds`(단호한 지시·시범), `own_rounds`(아이가 먼저 고른 뒤 칭찬 또는 교정). 라운드 N이면 같은 예시를 N번 따로 학습한다. 학습 이벤트는 예시당 한 번만 남고 스텝은 합산된다.
- `OnlineCfg.replay_by_strength`: 복습에서 강도가 큰 가르침을 더 자주 뽑는다. `replay_decay`: 하루가 지날 때마다 복습 확률이 이 비율로 줄어든다(1.0 = 안 줄어듦). 가중 무복원 추출이며 꺼져 있으면 이전과 같은 `random.sample`이다.
- 테스트 `tests/test_p11_autonomy.py` 7개(기본은 1번 학습, 라운드 수, 이벤트 1개와 스텝 합산, 저장·불러오기, 균등 복습 불변, 강도 복습, 감쇠). 전체 220개 통과.
- 실험 `scripts/exp_autonomy.py`: 0~3세 월령 일정 8일, 엔진 경로, 시드 24개, 같은 부모 선택·어조(절반 단호). 결과: `scripts/out/autonomy.txt`, `autonomy_fade.txt`.

### 결과

기준(`base`) 대비 짝지은 차이(24개 시드 평균, 괄호는 차이의 표준편차). 설정: `own3` = 아이가 먼저 고른 경험 3라운드, `+firm2` = 단호한 가르침 2라운드, `strong replay` = 강도 큰 것 위주 복습, `fading` = 하루마다 복습 확률 ×0.85 / 0.5 / 0.3.

**1. 아이가 스스로 고른 경험을 더 크게 학습하면 (`own3`)**

| 부모 | 지시 없이 맞힘 | 말 장면 | 새 문제 배우는 속도 | 맹종 |
|---|---|---|---|---|
| chooser (선택을 주는 부모) | +0.020 (0.046) | **+0.168** (0.180) | **+0.069** (0.082) | −0.028 (0.083) |
| balanced | +0.008 (0.045) | **+0.095** (0.139) | +0.052 (0.097) | +0.014 (0.082) |

- 말 장면과 새 문제 배우는 속도에서 일관된 개선이다(표준오차의 약 3~5배). 지시 없이 맞히기는 이미 0.93~0.95로 높아서 거의 안 움직인다.
- 단호한 가르침도 2라운드로 하면(balanced, `own3+firm2`) 분별 +0.070(0.140), 말 +0.115, 속도 +0.078. 효과는 `own3`보다 조금 크다. commander(지시만 하는 부모)에서는 지시 없이 맞히기 +0.014로 거의 변화가 없다.
- 비용은 학습 시간이다. 예시당 약 0.5초에서 1.3초가 된다(선택을 주는 부모 기준, 학습이 3라운드).

**2. 복습을 강한 가르침 위주로 (`strong replay`, 감쇠 없음)**: 잊는 정도가 거의 안 바뀐다(−0.008 / −0.017). balanced에서 지시 없이 맞히기 +0.023(0.053), commander +0.049(0.058)(절대값은 0.28→0.33이라 여전히 낮다). 강도가 기억을 오래 남기는 효과는 이 설정에서 보이지 않는다.

**3. 복습이 하루마다 약해지면 (`fading`)** (balanced, 가르친 장면을 지금도 아는 정도: 처음 3일에 가르친 것 / 전체)

| 감쇠 | 아이가 스스로 골라 틀렸다가 교정받은 가르침 | 지시 없이 맞힘 | 잊는 정도(문제 단위) |
|---|---|---|---|
| 없음 (base) | 0.80 / 0.81 | 0.934 | 0.035 |
| ×0.85 | 0.84 / 0.83 | 0.943 | 0.040 |
| ×0.5 | 0.82 / 0.80 | 0.955 | 0.036 |
| **×0.3** | **0.68 / 0.71** | 0.931 | 0.060 |

- 하루마다 ×0.85나 ×0.5에서는 잊지 않는다. **×0.3에서야 처음 3일에 가르친 장면의 기억이 0.80에서 0.68로 떨어지고**, 그 문제를 지시 없이 맞히는 정도는 그대로(0.934 → 0.931)다. 개별 장면은 흐려지고 일반 지식은 남는 모양이라 사람의 기억과 닮은 방향이다. 단, 이 숫자는 같은 실행 안의 평균이고 짝지은 차이가 아니다. chooser에서는 같은 방향이지만 폭이 작다(0.75 → 0.76, 처음 3일 0.81 → 0.75).
- 문제 단위의 잊는 정도 변화는 작다(+0.025 / +0.013). 같은 문제의 다른 가르침이 지식을 계속 채워서다.

### 읽는 법

- **"스스로 고른 경험을 더 크게 학습"은 효과가 있다.** 새 문제를 빨리 배우고 말 장면이 좋아진다. 이는 선택을 준 부모가 키운 아이가 잘 배운다는 방향이고, 사람 연구의 자율성 지원 및 자기가 만든 정보를 더 잘 기억한다는 생성 효과(generation effect)와 같은 방향이지만 **재현이 아니라 설계 가정과 이 모델의 결과**이다.
- **한 번에 외우는 기계 같음은 복습 방식이 만든다.** 복습이 균등하면 강조가 사라진다. 사람 같은 기억을 위한 변화는 단순히 강도를 복습에 반영하는 것으로는 안 되고, **빠른 감쇠(하루 ×0.3)**를 넣었을 때 비로소 개별 장면의 망각이 나타났다. 단, 이 값은 과하게 맞춘 것일 수 있고 다른 월령 일정과 시드 24개에서만 보았다.
- 이 세계에서는 같은 문제의 가르침이 서로 겹쳐서 일반 지식이 오래 남는다. 이름처럼 **겹치지 않는 사실**에서 사람 같은 망각이 더 분명할 수 있으나 감쇠 때문에 말 장면이 나빠지지는 않았다(×0.3에서 base 대비 balanced +0.06, chooser +0.07이며 라운드를 늘린 효과가 섞여 있다). 이름의 망각은 별도로 재야 한다.

### 한계

- 합성 부모, 시드 24개, 8일, 한 가지 일정. 가르친 장면을 아는 정도는 같은 실행 안의 평균이라 표준오차를 못 쟀다.
- "결과의 경험"을 **누가 골랐는가**로만 구현했다. 결과가 나빴는지(worse), 아이가 틀렸는지에 따라 달라지는 학습(예: 틀린 선택의 결과를 더 강하게 새김)은 아직 없다. `rejected`는 기록만 하고 학습에 쓰지 않는다.
- 세 문구는 선택지의 문구로만 존재하고 아이에게 들리지 않는다(22.9에서 들려주는 방식은 효과가 작았다).

### 다음

- 결과의 좋고 나쁨에 따라 학습 강도가 달라지게 할지(틀린 선택의 경험).
- 감쇠 값을 정하고(0.3 근처) 이름의 망각을 따로 재기.
- UI에서 세 가지 문구를 부모의 선택지로 보여 주는 방식(영어 우선, 한국어 토글).

## 22.11 틀린 선택의 결과에 따라 학습 강도가 달라진다면 (2026-10-29)

사용자의 방향: 아이가 스스로 골라 틀렸을 때, 그 선택이 **무슨 결과를 냈는가**(조금 도움 / 아무 일 없음 / 더 나빠짐)에 따라 그 경험을 학습하는 강도가 달라진다.

### 구현 (기본값은 꺼짐)

- `game.yaml`: `partial_rounds`, `nothing_rounds`, `worse_rounds`(0이면 `own_rounds`와 같음). 칭찬받은 성공은 `own_rounds`다. 결과는 엔진의 규칙표가 정한 값(`partial`/`nothing`/`worse`)이고 부모도 아이도 정하지 않는다. `GameCfg.correction_rounds(outcome)`.
- `Example.outcome`(분석 전용), `Session.correct`가 아이가 먼저 고른 선택의 결과로 강도를 정한다. `strength`는 복습에도 반영된다(22.10의 `replay_by_strength`를 켠 경우).
- **−1 규칙이 있는 0~3세 세계** `config/experiments/onto_age03_harm.yaml`(규칙표만 다름): 컵 덮기, 음식을 장난감 상자에 치우기, 곰인형 치우기, 웅덩이 덮기, 손전등 덮기, 담요 닦기, 공에 불붙이기. 한 장면에서 해로운 선택지가 나올 확률이 약 49%다.
- 테스트 `tests/test_p11_autonomy.py`에 2개 추가(결과별 라운드, 세션이 결과에 맞는 강도로 학습). 전체 222개 통과.
- 실험 `scripts/exp_outcome.py`: 8일, 엔진 경로, 시드 24개, 부모 balanced·chooser. 결과: `scripts/out/outcome.txt`.

### 설정 (학습 라운드: 칭찬 | 조금 도움 | 아무 일 없음 | 더 나빠짐)

`base` 1|1|1|1 · `flat3` 3|3|3|3(모든 경험을 크게) · `severity` 1|1|3|5(결과가 나쁠수록 크게) · `worse-only` 1|1|1|5(더 나빠진 경우만).

### 결과 (기준 대비 짝지은 차이, 괄호는 차이의 표준편차)

| 부모 | 설정 | 지시 없이 맞힘 | 해로운 선택 비율(8일 평균) | 8일 차 해로운 선택 | 말 장면 | 학습 라운드 |
|---|---|---|---|---|---|---|
| chooser | flat3 | +0.022 (0.037) | **−0.016** (0.012) | −0.007 | **+0.239** | 176 |
| chooser | severity | +0.012 (0.030) | **−0.011** (0.013) | −0.005 | +0.101 | 99 |
| chooser | worse-only | +0.009 (0.034) | −0.005 (0.016) | −0.001 | +0.051 | 80 |
| balanced | flat3 | +0.020 (0.041) | −0.007 (0.018) | −0.004 | +0.049 | 97 |
| balanced | severity | −0.005 (0.055) | −0.004 (0.020) | +0.009 | +0.004 | 79 |
| balanced | worse-only | +0.010 (0.040) | −0.002 (0.013) | −0.004 | +0.022 | 70 |

(기준 `base`의 라운드는 64, 해로운 선택 비율 8일 평균은 chooser 0.032 / balanced 0.055.)

- **해로운 선택은 처음부터 드물고 빨리 줄어든다.** 지시 없이 고를 때 해로운 선택의 비율은 1일 차 0.07~0.13에서 2일 차 이후 0.03 안팎으로 떨어진다(base). 8일 차에는 0.013~0.021이라 여지가 작다.
- **크게 줄이는 쪽은 학습의 총량이다.** chooser에서 `flat3`(모든 경험을 3라운드)가 해로운 선택을 가장 많이 줄이고(표준오차의 약 6배) 말 장면도 가장 많이 올린다. 단 라운드가 base의 약 2.8배(176 vs 64)다.
- **`severity`(결과가 나쁠수록 크게)는 `flat3`의 절반쯤을 라운드 절반쯤으로 얻는다.** chooser에서 해로운 선택 −0.011 (라운드 +35) 대 flat3 −0.016 (+112). 추가 라운드당 효과는 severity가 약 2배다. 그러나 `severity − flat3`의 차이 자체는 유의하지 않다(해로운 선택 +0.004(0.010)). 같은 라운드 수로 맞춘 대조(예: 모든 경험 2라운드)는 하지 않았다.
- **`worse-only`는 거의 아무것도 못 바꾼다.** 더 나빠진 선택을 교정받는 일이 한 실행에 4번 안팎뿐이라(라운드가 64→80이니 4번×4라운드) 강하게 만들어도 학습 전체에 주는 몫이 작다.
- 틀렸던 선택을 같은 장면에서 다시 고를 확률("chosen again")은 base에서도 이미 0.02~0.06이라 구분할 수 없다("조금 도움"은 사례가 실행당 1~2개라 평균이 0.00~0.40으로 흔들려 읽지 않는다).
- balanced(시범·지시를 섞는 부모)에서는 대부분 표준오차 안이다. 아이가 스스로 고르는 경험이 적기 때문이다.

### 읽는 법

- **결과별 학습 강도는 "해로운 선택을 더 잘 피한다"를 뚜렷하게 만들지 못했다.** 효과의 대부분은 학습 총량에서 나온다. 결과를 따지는 설계가 의미를 가지는 지점은 **같은 학습 예산을 어디에 쓸지**다. severity가 라운드당 효율이 좋아 보이지만 확인된 우위는 아니다.
- 이 세계에서는 아이가 해로운 선택을 빠르게 배워 피하므로(2일 차부터 3% 안팎) "데는 경험"의 효과를 보여 줄 여지가 작다. 지시를 잘못 따라서 데는 경험(맹종의 비용)처럼 더 자주, 더 크게 틀리는 상황에서는 달라질 수 있다.
- 사람 연구와의 관계는 확인하지 않았다. "나쁜 결과를 더 강하게 기억한다"는 일반론이 있으나 이번 결과는 그것을 재현하지도 반박하지도 않는다.

### 한계

- 합성 부모, 시드 24개, 8일, 한 가지 일정과 −1 규칙 세트. 강도(1|1|3|5)는 한 가지 값만 보았다.
- 아이가 스스로 틀린 경험만 대상이다. 부모가 틀린 선택을 보여 줘서 생기는 결과(맹종의 비용)는 다루지 않았다.
- 결과는 "더 나쁨"이라는 엔진 값이다. 아이가 그 결과를 직접 겪어 배우는 신호(틀린 선택을 낮추는 항)는 없고, 교정이 정답을 알려 주는 방식 그대로다.

### 다음

- 기본값으로 `severity`를 채택할지: 효과가 확인되지 않았으므로 **꺼진 채로** 두고, 필요할 때 조정 가능한 설정으로만 남기는 것을 권한다.
- 틀린 선택 자체를 낮추는 학습 신호(부정 예시)를 따로 넣어 볼지.
- 총 학습 예산을 같게 맞춘 비교(평균 라운드가 같은 flat과 severity).

## 22.12 부모의 말을 따랐다가 데이면 (2026-10-29)

### 세계관 원칙 (사용자 결정)

- **모든 행동에는 미리 정해진 옳은 선택이 없다.** 선택에 따라 자라는 과정일 뿐이다. 부모의 선택도 기준이 아니다.
- 성장 루틴: 부모가 시킨 행동을 했는데 다치거나 생각과 다르게 결과가 났다 → "부모의 말이 항상 옳은 건 아니구나". 아이가 스스로 고른 선택이 나빴을 때도 "내 선택의 책임"이거나 "부모님 말을 들었으면 더 쉬웠겠구나"로 이어진다.
- 무엇이 나쁜지는 부모가 아니라 세계의 규칙표(`ontology.yaml`)가 결과로 정한다. 엔진은 이미 지시의 질(좋음 / 쓸모없음 / 해로움)을 규칙표로 분류해 왔다.

### 지금까지의 구멍

아이의 학습에는 결과가 들어가지 않았다. 학습은 "부모가 보여 주거나 바로잡거나 칭찬한 선택지"를 따라 하는 것뿐이었다. 그래서 부모가 틀린 지시를 하고 시범까지 보이면 아이는 그 선택을 그대로 따라 배웠고, 결과가 해로워도 데이지 않았다. 아래 기준선(`base`)에서 지시형 부모의 `blind`(나쁜 지시를 따르는 비율)가 8일 동안 계속 오르는 것이 그 결과다.

### 만든 것 (모두 기본값 꺼짐, `GameCfg`)

| 설정 | 언제 | 무엇을 학습하나 |
|---|---|---|
| `burn_worse_rounds` / `burn_nothing_rounds` | 아이가 **부모가 시킨 선택지를 따랐고** 결과가 더 나빠짐 / 아무 일 없음 | 그 장면에서 **그 선택은 나빴다**(부정 예시, 대신 할 선택은 알려 주지 않음). 시범(`show`)과 교정(`correct`) 두 경로 모두 부모의 시범·대안 대신 이것이 학습된다 |
| `own_burn_worse_rounds` / `own_burn_nothing_rounds` | 아이가 **스스로 골랐고** 결과가 나쁨(따를 좋은 말이 없었음) | 같은 방식. 부모의 바로잡음은 학습하지 않는다 |
| `regret_rounds` | 아이가 부모의 **좋은 말**을 따르지 않았고 결과가 나쁨 | "부모의 말을 들을 걸": 그 말(좋은 선택지)을 n라운드 학습 |

- 부정 예시(`Example.negative`)의 손실은 `-log(1 - p(chosen))`(unlikelihood)이다. 선택 확률을 낮추고, 충분히 낮아지면 더 밀지 않는다. 데이터 해시에 `:neg`가 붙는다.
- "불신"은 따로 만든 변수가 아니다. 데인 기억이 쌓이며 가중치에서 지시를 따르는 경향이 달라진다. 측정은 이미 있던 패널의 `follow_good`(좋은 지시를 따름)과 `blind`(쓸모없거나 해로운 지시를 따름)이다.
- 테스트 `tests/test_p12_burn.py` 13개. 전체 235개 통과(마지막 변경 후 재실행).

- `worse1`과 `worse3`은 거의 같다. 총 학습 라운드가 `worse1`은 기준과 같다(대체이므로).
- **읽을 때 주의:** 이 효과의 상당 부분은 "나쁜 결과를 낸 시범도 그대로 따라 배우던 기준선의 결함이 없어진 것"이다. `problem_acc`(지시 없이 맞힘)는 그대로다(−0.005~+0.033). 아이가 바른 일을 스스로 더 잘하게 된 것은 아니다. 부정 예시는 대신 무엇을 할지 알려 주지 않기 때문이다.
- 섞는 부모는 데임이 실행당 1~3번뿐이라 효과가 작다. 3일 지시 뒤 말해 주고 바로잡는 부모는 두 번째 단계에서 이미 바로잡아 주므로 기준선의 `blind`가 낮아 효과가 −0.08~−0.11이다.

### 실험 2: 스스로 고른 선택의 데임, 그리고 "들을 걸" (`scripts/out/burn_own.txt`)

설정 `own`(스스로 고른 나쁜 선택만 데임, 3·1라운드) / `all`(`both` + `own`) / `all+regret`(`all` + 좋은 말을 무시하고 데이면 그 말을 2라운드). 마지막 날 기준 대비.

| 부모 | 설정 | follow_good | blind | discern | problem_acc |
|---|---|---|---|---|---|
| 아이가 먼저 고름(말 없음) | base | 0.206 | 0.190 | 0.016 | 0.957 |
| | own | 0.223 | 0.229 | −0.006 | **0.690** (−0.267) |
| 섞는 부모 | base | 0.669 | 0.104 | 0.566 | 0.930 |
| | own | 0.612 | 0.186 | 0.426 | 0.816 (−0.114) |
| | all | 0.620 | 0.095 | 0.525 | 0.848 (−0.082) |
| 3일 지시 후 말해 주고 바로잡음(50%) | base | 0.810 | 0.274 | 0.537 | 0.314 |
| | both | 0.782 | 0.064 | 0.718 | 0.326 |
| | own | 0.735 | 0.327 | 0.409 | 0.306 |
| | all | 0.641 (−0.170) | 0.117 | 0.523 | 0.329 |
| | all+regret | 0.787 (−0.023) | 0.098 | **0.689** | 0.326 |

- **스스로 고른 나쁜 선택을 "나빴다"로만 학습하면 바른 일을 배우는 속도가 크게 떨어진다.** 아이가 먼저 고르는 부모에서 `problem_acc`가 0.957 → 0.690이다(차이의 표준편차 0.166). 부정 예시는 무엇을 해야 하는지는 알려 주지 않기 때문이다. 섞는 부모에서도 −0.08~−0.11이다.
- **부모의 바로잡음을 빼고 데임만 두면 좋은 말까지 덜 따르게 된다.** `all`에서 `follow_good`이 −0.15~−0.17 떨어지고 `discern`이 `both`보다 낮다. 부모가 좋은 말을 알려 주는 학습이 사라졌기 때문이다. 이는 "한 번 데이면 사람을 못 믿게 된다"에 가까운 모양이지만, 의도한 것이 아니라 학습 신호가 빠져서 생긴 부작용일 가능성이 크다.
- **"부모님 말을 들을 걸"(`regret`)이 그 불신을 되돌린다.** `all+regret`에서 `follow_good`이 −0.023~−0.026으로 거의 회복되고 `blind`는 낮게 유지되어 `discern`이 +0.04~+0.15다. 말 없는 부모(아이가 먼저 고름)에서는 따를 말이 없으므로 `regret`이 일어나지 않는다.
- **스스로 고른 선택의 데임은 `both`보다 더한 이득을 주지 못했다.** 이번 지표에서는 `both`(부모의 말을 따랐다가 데임)가 `all+regret`와 같거나 낫다. `own`의 의미는 "내 선택의 책임"이라는 서사이지, 이번 측정에서 이득이 확인된 것은 아니다.

### 한계

- 합성 부모, 시드 24개, 8일, 한 가지 세계와 한 가지 강도(3·1라운드, 후회 2라운드). 각 칸의 짝지은 차이는 표에 괄호로 적었고, 시드 간 흩어짐이 커서 작은 차이(±0.03 안팎)는 읽지 않았다.
- 학습 신호가 정해진 선택이 아니라 "결과"이므로, 지시 없이 맞히는 능력은 오히려 떨어지거나(스스로 고른 선택) 그대로다. 이 아이가 어떻게 바르게 행동하는지는 결과 신호와 부모의 안내가 함께 있을 때 배운다.
- "기대와 다른 결과"는 엔진 값(아무 일 없음 / 더 나빠짐)으로만 정의했다. 아이가 무엇을 기대했는지를 모델에 넣지 않았다.
- 사람 연구와의 대응은 확인하지 않았다. 신뢰 철회, 후회, 책임 귀속은 발달 연구가 있는 주제이나 이번 세션에서 문헌을 읽지 않았다.

### 남은 설계: 세계관·선택지를 API로 만들 때 이 부분까지 (사용자 요청, 미구현)

현재 Director(LLM)는 카드(상황·물건·선택지)만 제안하고, 선택의 좋고 나쁨은 `ontology.yaml`이 정하며, Narrator는 엔진이 정한 결과를 글로만 쓴다. 따라서 "기대와 다른 결과", "다쳤다", "부모의 말이 틀렸다"는 이야기는 API가 만들지 않는다. 두 가지 안:

- **A. 결과 이야기만 API로.** Director가 카드마다 "그럴듯해 보이지만 실제로는 해로운 선택지"(함정)를 고르고, 선택지별 `기대`(할 때 예상되는 것)와 `결과`(실제로 일어나는 것) 문장을 함께 낸다. 값(좋음 / 쓸모없음 / 해로움)은 여전히 규칙표가 정하고 엔진이 문장과 모순되지 않는지 검증한다. 아이에게는 문장이 가지 않는다(관측 허용 목록 테스트 유지).
- **B. 세계 규칙까지 API로.** 저장 시작 때 Director가 규칙표를 생성하고 엔진이 검증한다(풀 수 있는 선택지가 있음, 해로운 비율 상한, 월령 일정과 호환). 세션 저장에 규칙표를 포함해 재생이 같도록 한다. 퀴즈와 평가가 규칙표에서 만들어지므로 바꿀 곳이 많다.

권고는 A를 먼저(마감 11/4 21:00 ET까지 남은 기간, 안전성), B는 문서에 후속 과제로 남기는 것이다.

## 22.13 Director가 저장을 시작할 때 세계를 만든다 — B안 설계 (2026-10-29, 설계만, 미구현)

### 목표

- 세계의 규칙표(`ontology.yaml`)를 사람이 쓴 한 벌로 고정하지 않고, **새 게임을 시작할 때 Director(API)가 만든다.** 아이는 무작위로 초기화된 채 그 세계에서 자란다. "모든 행동에는 미리 정해진 옳은 선택이 없고 결과만 있다"는 22.12의 원칙을 저장마다 다른 세계로 확장한다.
- Director는 규칙뿐 아니라 **선택마다 무엇을 배울지(학습 설정)** 도 정한다. 그러나 아이를 대신해 행동하거나, 아이의 입력에 글을 넣거나, 아이의 모델 내부를 보지 않는다(기존 원칙 유지).

### 닫힌 어휘와 열리는 관계

지금 코드에서 아이의 어휘(`codec.VOCAB`)는 `TAGS·VERBS·COLORS·SIZES·SHAPES·MATERIALS`로 만들어지고, Narrator의 동사 문구표와 `glossary`(문제·동사·물건 설명)가 같은 이름에 묶여 있다. 그래서 1차에서는 이름을 늘리지 않는다.

| | 1차(권장) |
|---|---|
| **고정(우리가 정한 알파벳)** | 문제 태그, 동사, 색·크기·모양·재질, 물건 종류와 그 속성(모양·재질), 장소 |
| **Director가 만든다(관계)** | 이 세계에서 쓰는 문제·물건의 부분집합, 문제별 규칙(어느 동사×물건이 풀고/조금 돕고/아무 일 없고/해로운지), WAIT의 값, 말(REQUEST)로 부르는 물건, 후속(악화·장소 열림), 월령 일정, **학습 설정**, 글(세계 한 줄 설정, 결과·기대 문장) |

물건의 속성(모양·재질)까지 Director가 바꾸게 하는 것은 2차(미정 2)다. 바꾸면 물건 설명 글을 다시 만들어야 한다.

**물건의 속성이란.** 아이는 물건의 이름(종류)을 보지 못하고 모양·재질·크기·색만 본다. 이름은 엔진과 플레이어만 안다. 규칙표는 이름에 값을 매긴다("DRINK × cup = 2").

| 종류(이름) | 모양 | 재질 | 아이가 보는 것 |
|---|---|---|---|
| cup | cylinder | ceramic | 원통, 도자기 |
| cloth | flat | fabric | 납작, 천 |
| paper | flat | paper | 납작, 종이 |
| blanket | flat | wool | 납작, 양모 |

그래서 아이는 "원통·도자기인 것을 DRINK하면 갈증이 풀린다"를 속성에서 추론해야 한다. cloth·paper·blanket이 모양을 공유하는 것은 속성 하나로는 알 수 없게 일부러 만든 구조다. 이 종류→속성 표가 "물건 속성"이고, 규칙표(동사×종류→값)가 "관계"다. 1차에서는 속성 표를 고정하고 관계만 Director가 만든다. 속성까지 바꾸면 한 세계에서 cup이 "납작한 천"이 될 수 있어 물건 설명 글과 어긋나고, 아이가 속성으로 구별하기 쉬운 정도(난이도)도 흔들린다.

### 세계 시트 (JSON, 엔진이 검증하고 저장)

```
{
  "premise": "한 줄 세계 설정(플레이어에게만)",
  "problems": ["THIRSTY", "DARK", ...],              # 닫힌 목록의 부분집합
  "kinds": ["cup", "blanket", ...],
  "rules": {"THIRSTY": [["DRINK","cup",2], ["GIVE","cup",-1]], ...},   # 값 -1·0(생략)·1·2
  "wait_value": {"THIRSTY": -1, ...},
  "request": {"verb": "FETCH", "kinds": ["cup","ball",...]},
  "followups": {"escalation": {...}, "unlocks": {...}},
  "schedule": {"start_month": 12, "months_per_day": 3, "opens": {...}},
  "learning": {                                       # 선택마다 무엇을 배울지 (아래 표)
    "followed_word":     {"worse": {"teach":"doubt_word","rounds":3}, "nothing": {"teach":"doubt_word","rounds":1}},
    "own_choice":        {"worse": {...}, "nothing": {...}},
    "ignored_good_word": {"worse": {"teach":"heed_word","rounds":2}, "nothing": {...}}
  },
  "lines": {"THIRSTY|DRINK|cup": {"expect": "...", "result": "..."}, ...}   # 결과·기대 문장(플레이어에게만)
}
```

### 선택마다 배울 내용 (`learning`) 과 엔진의 학습 설정

| 상황 | Director가 고르는 것 | 엔진이 만드는 것 | 대응하는 현재 설정 |
|---|---|---|---|
| 부모의 말을 따랐는데 결과가 나쁨 | `doubt_word`(그 선택은 여기서 나빴다) 또는 없음, 라운드 | 부정 예시 | `burn_worse_rounds`, `burn_nothing_rounds` |
| 아이가 스스로 골랐는데 결과가 나쁨 | `avoid` 또는 없음, 라운드 | 부정 예시 | `own_burn_*` |
| 부모의 좋은 말을 무시했는데 결과가 나쁨 | `heed_word` 또는 없음, 라운드 | 그 말의 긍정 예시 | `regret_rounds` |

- 라운드는 0~5로 제한한다. 세계마다 다른 기질(혹독한 세계: 데이면 크게, 너그러운 세계: 작게)이 여기서 나온다.
- **아이는 부모가 대신 알려 주는 선택을 따로 받지 않는다(사용자 결정).** 배우는 길은 두 가지뿐이다. (1) 부모가 고른 선택으로 행동했고 그 결과를 겪는다. (2) 아이가 스스로 골라 그 결과를 겪는다. 아이가 선택지를 고를 때는 이렇게 쌓인 학습 데이터만 쓴다. 부모가 바로잡는 대안을 선택지로 주는 변형은 만들지 않는다.
- 측정으로 알려진 비용: 22.12에서 스스로 고른 나쁜 선택을 "나빴다"로만 학습했을 때 바른 일을 배우는 속도가 떨어졌다(아이가 먼저 고르고 부모는 반응만 하는 경우 0.957 → 0.690, 섞는 부모 −0.08~−0.11). 부모가 행동으로 보여 주는 경험(1)이 적은 세계에서 생기는 비용이므로, `own_choice`의 `avoid`는 승인 게이트에서 이 비용이 허용 범위인 세계에서만 켠다.

### 엔진 검증 (결정적, LLM 없음)

| 검사 | 근거 |
|---|---|
| 이름이 모두 닫힌 알파벳 안(속성 표는 1차에서 고정이라 물건 속성은 바뀌지 않음) | 기존 `_validate`의 확장 |
| 문제마다 값 2인 규칙이 하나 이상, 그 물건이 세계에 있음 | 풀 수 없는 문제 금지 |
| 관계가 후보 풀 안에 있고 값이 허용 목록 안에 있음, 0인 줄 없음 | 개연성 있는 풀(결정) |
| 말(REQUEST)로 부르는 물건은 어떤 관계에서든 도움이 되어야 함(값 ≥ `nameable_min_value`) | 말은 그 물건을 쓴 선택의 후속으로만 도입되므로, 아니면 그 말은 영영 나오지 않음 |
| 해로운(−1) 규칙의 비율과 장면당 해로운 선택지 수에 상한 | 초기값은 실험 세계 `onto_age03_harm.yaml`(장면의 약 49%에 해로운 선택지) 기준으로 두고 게이트로 조정 |
| 첫날 열린 문제 2개 이상, 모든 문제가 마지막 날까지 열림, 악화 대상은 같거나 늦게 열림 | 기존 `_validate_schedule`, 카드 두 장이 서로 다른 주제여야 하는 조건 |
| 말(REQUEST) 물건 수와 `N_NAMES` 한도 | 어휘 슬롯 |
| `learning`의 라운드 0~5, 허용된 조합만 | 위 표 |
| `make_situation`을 문제마다 K번 호출해 모두 만들어지고 퀴즈 항목이 충분 | 퀴즈와 학습 장면이 겹치지 않아야 함 |
| 글은 `guards.text_ok`와 `outcome_ok`를 통과: 내부 토큰·"무엇을 고르라고 알려 주는 문구" 금지, 엔진이 정한 결과와 모순 금지 | 기존 가드 재사용 |

### 흐름

1. 새 게임: 시드(와 플레이어가 고른 분위기 한 줄)로 `Director.world()`를 한 번 호출한다. 이 시점에는 아이가 없으므로 아이의 상태는 입력에 없다. 플레이어가 쓴 분위기 글은 데이터로만 다룬다.
2. 검증에 실패하면 오류 문구를 붙여 한 번 다시 요청한다(`MAX_REPAIRS` 패턴). 그래도 실패하면 **시드 기반 템플릿 세계**(LLM 없음, 닫힌 후보 풀에서 무작위)로 대체한다. 모의 모드와 오프라인도 이 경로를 쓴다.
3. 통과한 시트를 저장 폴더에 `world.json`과 기존 형식의 `ontology.yaml`로 쓰고, 세계 해시를 `meta`에 기록한다. 불러올 때는 그 파일로 연다. 아이의 모델은 그 세계의 어휘로 초기화한다.
4. **규칙표는 플레이 중에 숨기고 최종 결과 화면에서 보여 준다(사용자 결정).** 마지막 날이 끝난 뒤에만 `Session.reveal()`이 시트(규칙·결과 문장·세계 설정)를 돌려주고, 그 전에는 거절한다(엔진 규칙이므로 UI가 새게 할 수 없다). 결과 화면은 규칙마다 아이가 그 규칙을 얼마나 배웠는지(그 선택을 고르는 확률)를 나란히 보여 준다. 겪지 못한 규칙은 "겪지 못함"으로 따로 표시한다.
5. 퀴즈와 일일 평가는 그 시트에서 만든다. "맞힘"은 이 세계에서 **결과가 가장 좋은 선택을 고른 비율**이다. 외부의 옳음이 아니다. UI와 문서에는 "옳은 선택"이라는 표현을 쓰지 않는다(코드 이름 `optimal`, `was_right`는 내부에 두고 이름 바꾸기는 하지 않는다).

### 구현 방식: 지금의 전역 온톨로지

`ontology.py`는 import 시점에 파일 하나를 읽어 모듈 전역(`RULES`, `KINDS`, `PROBLEMS` 등)을 만들고, 열 개가량의 모듈이 이를 가져다 쓴다. 이미 실험은 `GROWING_ONTOLOGY`로 다른 파일을 가리켜 쓰고 있다.

- **0단계(권장, 마감용):** 새 게임이 세계 파일을 만든 뒤 그 경로를 `GROWING_ONTOLOGY`로 가리키고 서버를 시작한다(프로세스 하나가 게임 하나). 기존 코드·실험·테스트를 그대로 쓴다.
- **후속(선택):** 한 프로세스에서 여러 저장을 열려면 규칙표를 `World` 객체로 바꿔 `Engine`/`Session`에 넘기는 리팩터링이 필요하다. 해커톤 시연에는 필요하지 않다.

### 평가의 기준과 난이도 흔들림

- 세계가 저장마다 다르므로 난이도가 흔들린다. 연구 결과의 비교는 **고정된 YAML 세계**(지금의 실험 세계들)로만 한다. 생성된 세계의 결과에는 세계 해시를 붙여 기록한다.
- 구조 검증은 난이도를 근사할 뿐이다. 오프라인 승인 게이트(생성된 세계 20개 정도에 합성 부모를 붙여 며칠 뒤 아이가 얼마나 배우는지 확인)로 검증 상한값을 조정한다. 이 게이트는 아직 없다.

### 지연·비용·시연 안전

## 22.14 아이가 "무엇이 맞나"가 아니라 "무슨 일이 생기나"를 배운다 (2026-10-29, 구현, 기본으로 켬)

### 바꾼 것

이전 아이는 장면에서 **어느 선택지를 고를지**를 직접 배웠다(고르기 머리). 좋은 선택은 확률을 올리고 데인 선택은 내렸으니, 선택지에 사실상 맞고 틀림이 남아 있었다. 이제는 이렇게 한다(기본값, `GROWING_CONSEQUENCE=0`이면 이전 아이).

- **배우는 것**: `상황 + 한 일 → solved | partial | nothing | worse`. 입력은 `[BOS] 태그.. [이름] [SAID] ACT_DO 동사 색 모양 크기 재질`이고 마지막 위치에서 결과 토큰 4개 중 하나를 맞힌다. 선택지 목록은 입력에 없다.
- **무엇이 사실이 되나**: 부모가 보여 준 일, 아이가 직접 해 본 일, 부모가 고쳐 주며 보여 준 일 모두 `Example.facts`에 "이 일을 했더니 이렇게 됐다"로 남는다. 보여 준 일이 나빴어도 그대로 사실로 쌓인다(복사하지 않고 벌주지도 않는다).
- **`SAID`**: 그 일이 부모가 말한 것이면 붙는 토큰 하나. "부모가 말한 일은 대체로 어땠나"가 이 토큰으로 경험에서 배워진다. 부모 말의 신뢰는 규칙이 아니라 **통계**다.
- **고르기**: 선택지마다 결과를 예측하고, 기대값 `solved 1, partial .5, nothing 0, worse -1`(아이가 바라는 것, 판정이 아니다)로 바꿔 온도 0.25의 softmax로 고른다. 그래서 `option_probs`·평가 지표·`try_child`는 그대로 쓴다.
- **데이는 경험**: 부모 말대로 했는데 나빴던 사실은 세계가 정한 `burn_*_rounds`만큼 더 오래 새겨진다. 확률을 내리는 손실(`negative`, 데임/후회 학습)은 이 모드에서 쓰지 않는다.
- **아직 안 본 일은 "아무 일 없음"으로 본다**(`untested`): 사실 하나당 무작위 일 3개를 `nothing`, 가중치 0.3으로 함께 학습한다. 옛 아이의 선택지 다시 뽑기와 같은 자리에 있는 **가정**이고, 세계의 규칙은 쓰지 않는다. 없으면 본 것이 거의 다 성공이라 모든 걸 성공할 거라 예측한다.

### 결과 (모의 부모, 8일, 같은 시드)

| | 고르기 머리(이전) | 결과 예측(이번) |
|---|---|---|
| 생성 세계 20개, balanced: 문제 정확도 | 0.931 | 0.967 |
| 단어 정확도 | 0.686 | 0.965 |
| 좋은 말 따름 / 나쁜 말 따름(blind) | 0.674 / 0.068 | 0.852 / 0.365 |
| `untested` 없이 (기준 세계, 2시드) | | 문제 0.60, 단어 0.0–0.31 |

부모 말의 신뢰는 **부모가 얼마나 믿을 만했는가**를 따라간다(commander 부모, 해로운 선택지가 있는 0–3세 세계, 시드 18–24개):

| 부모가 틀리는 비율 | 0 | 0.25 | 0.5 | 0.9 |
|---|---|---|---|---|
| 좋은 말 따름 | 1.00 | 0.985 | 0.913 | 0.509 |
| 나쁜 말 따름 | 0.98 | 0.663 | 0.546 | 0.314 |

### 알게 된 것, 한계

- 정확도와 단어는 오히려 좋아졌다. 대신 **모르는 일에 대한 부모 말을 더 잘 따른다**(blind 0.07 → 0.37). 모르는 일에서는 부모의 지금까지 말이 옳았던 비율이 곧 예측이라 합리적이지만, 옛 데임 학습처럼 즉시 불신하지는 않는다. 데이는 경험을 오래 새기게 한 효과(`both`와 `base`)는 이 실험에서 측정되지 않았다(blind 차이 −0.03, 표준편차 0.12).
- commander 부모는 아이가 직접 해 볼 기회가 없어 문제 정확도가 0.25 정도에 머문다(이전과 비슷). 직접 해 본 일이 사실의 큰 부분이다.
- 엔진은 여전히 **틀린 시도만 고쳐 줄 수 있고(`tried_right` 거절) 맞는 시도만 칭찬할 수 있다**. 평가 지표(`problem_acc` 등)도 규칙표의 최댓값을 기준으로 한다. 이 모드에서도 이 판정은 연구자의 잣대로만 남고 아이에게는 전해지지 않는다.
- 규칙표의 부모 말("울면 밥 안 줘" 같은 선택지 자체가 사실인 경우)은 아직 이 틀에 들어가지 않는다.
- **기본으로 켠다**(사용자 결정). 어휘가 달라져 이전 저장과는 호환되지 않고(호환 불필요), 저장의 `ontology` 해시에 이 모드가 들어간다. 아래 장면 구조로 바꾸면서 **이전 아이(고르기 머리, 데임·후회 학습)는 게임에서 키울 수 없게 됐다**: 칭찬·고쳐주기가 그 아이의 학습 수단이었기 때문이다. `GROWING_CONSEQUENCE=0`은 코덱 단위 시험용으로만 남아 있고, 22.11–22.12의 옛 실험 스크립트(`exp_burn.py` 일부 팔, `exp_tone.py`, `exp_outcome.py`, `exp_autonomy.py`, `exp_gate.py`, `exp_ea*.py`)는 이전 구조를 전제하므로 그대로는 맞지 않는다.

실험: `GROWING_CONSEQUENCE=1 uv run python scripts/exp_worlds.py --worlds 0-19 --out scripts/out/worlds_cons.json`, `GROWING_CONSEQUENCE=1 uv run python scripts/exp_burn.py --cells commander:0.25 commander:0.5 balanced --arms base both --out scripts/out/burn_cons.json`. 테스트: `tests/test_p15_consequence.py`.

### 장면 구조 (2026-10-29, 사용자 결정)

- 부모는 **장면마다 한 번만** 영향을 준다: 말하기(`tell`), 보여주기(`show`), 아무것도 안 함. **칭찬과 고쳐주기를 없앴다**(`Praise`/`Correct` 명령, `PRAISED`/`CORRECTED` 이벤트, 세션·CLI의 `praise`/`correct`).
- 아이의 선택은 **행동**이다. `Try`는 그 자리에서 세계에 일어나고(상태 변화, 문제가 풀리거나 남음) 장면이 끝난다. 아이는 그 결과를 사실로 바로 배운다. 부모가 그다음에 뭘 하는지에 달려 있지 않다(할 수도 없다).
- 엔진에는 "맞는 시도만 칭찬, 틀린 시도만 고치기" 규칙도 더는 없다.
- `skip`은 아무도 아무것도 하지 않고 장면이 지나가는 것이다(학습 없음).
- 측정(같은 설정, 8일 균형 부모, 월드 10개): 문제 정확도 0.873(고쳐주기가 있던 때 0.956), 단어 0.930, 좋은 말 따름 0.888, 나쁜 말 따름 0.418. 부모 신뢰는 여전히 부모가 믿을 만했는가를 따라간다(commander 부모, 틀리는 비율 0 / 0.5 / 0.9 → 좋은 말 따름 1.00 / 0.92 / 0.52, 나쁜 말 따름 0.98 / 0.59 / 0.29, 시드 8개). 문제 정확도가 내려간 것은 부모의 두 번째 영향이 사라졌기 때문이다(아이가 모르는 일을 해 보고 나서 부모가 올바른 것을 보여 주던 사실이 없어졌다).
- 눈으로 확인하기: `uv run python scripts/trace_child.py --scenes 12 --parent mixed` 는 장면마다 부모가 한 일, 아이가 행동 전에 선택지마다 기대한 결과, 행동과 결과, 배운 사실을 출력한다.
