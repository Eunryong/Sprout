## 1. 한 줄 컨셉

> **"LLM이 만들어지는 과정을 직접 겪으며 키우는 AI 아기."**
> 무작위 초기화된 아주 작은 Transformer가 플레이어의 시범·교정으로 **진짜 가중치 학습**을 하고, Meta 모델(Muse)은 그 아이가 사는 **세계·이야기·선생님 보조** 역할을 맡는다.

첫 성공 장면: *"어제 내가 가르친 걸 오늘 혼자 써먹었다."*

### 1.1 "LLM 발전 방식"을 게임 시스템으로 옮기기

실제 LLM 개발 파이프라인의 각 단계를 게임 메카닉으로 1:1 대응시킨다. 이게 이 게임의 차별점이자 심사용 스토리다.

| LLM 개발 단계 | 게임 안에서 | 실제 구현 |
|---|---|---|
| Random init | 갓 태어난 아이. 옹알이 수준의 무작위 행동 | seed 고정 무작위 가중치 체크포인트 `ckpt_0` |
| 데이터 수집 | 하루 동안의 경험·부모의 시범 | 리플레이 버퍼(JSONL) |
| Pretraining | 상황을 지켜본 것 (관찰 학습) | 관찰 시퀀스의 마스킹된 속성 예측 보조 손실 |
| SFT | 따라 하기 — 부모의 시범 | (관찰, 요청) → 정답 행동 지도학습 |
| Preference tuning | 교정 — "그거 말고 이거" | 교정에서 나온 (선택, 거절) 쌍 → DPO-lite **(stretch)** |
| Training run | 선택 직후의 학습 | 플레이어가 행동을 고르면 즉시 실제 optimizer step. loss 변화를 바로 표시 |
| Eval / Benchmark | NPC의 "퀴즈" | 학습에 안 쓴 배치의 평가셋 정답률 |
| Checkpoint | 성장 앨범 | 날짜별 체크포인트, 되돌리기 가능 |
| Regression / Forgetting | "어제 알던 걸 잊었다" | 이전 능력 정답률 하락 감지 → 일지에 기록 |

정직성 원칙(제안서 계승): 이 대응은 **축소 모형**이며 인간 발달·범용 지능을 재현한다고 주장하지 않는다. 학습 안 했는데 성장한 것처럼 보이게 하지 않는다.

### 1.2 핵심 재미: "가르친 방식대로 자란다"

v0.1에는 "왜 재밌는가"가 비어 있었다. 답은 **데이터의 질이 아이를 만든다**는 LLM의 실제 교훈을 게임 규칙으로 쓰는 것이다.

- 빨간 컵 하나만 보여주고 "뽀뽀"라고 하면, 아이는 "뽀뽀 = 빨간 것"으로 배울 수 있다 (가짜 상관, spurious correlation)
- 파란 컵·작은 컵도 보여주면 "뽀뽀 = 컵 모양"으로 일반화한다 (데이터 다양성)
- 같은 것만 반복하면 그 배치만 외운다 (과적합). 하루 상황이 6개로 제한되고 Director가 상황 카드를 2장 제안하므로, **어떤 상황을 골라 어떤 행동을 보여줄지**가 플레이어의 전략이다
- 이 과정이 "아이 머릿속" 패널(4.6)에 실제 모델 탐침 결과로 보인다

결과적으로 플레이어는 게임을 하면서 "왜 LLM에 다양한 데이터가 필요한가"를 몸으로 배운다. 아이의 실패는 버그가 아니라 **플레이어의 교육 데이터를 정직하게 반영한 결과**이고, 그래서 성공이 의미 있다.

## 2. 시스템 아키텍처

```
┌──────────────────────────── Web UI (상황 카드 · 행동 선택 · 학습 표시 · 성장 일지) ───────────────────────────┐
                                                  │ HTTP/WebSocket
┌──────────────────────────────────────── Game Server (FastAPI) ──────────────────────────────────────────┐
│                                                                                                          │
│   ┌───────────── Meta 서브에이전트 (Muse Spark via Meta Model API) ─────────────┐                        │
│   │  ① Director   사건 제안(JSON)        ③ Interpreter  부모 자유문장 → 교육 이벤트 │                        │
│   │  ② Narrator   확정 사실 → 서술        ④ Tutor        복습 변형 · 성장 일지 문장  │                        │
│   └──────────────┬──────────────────────────────────────┬────────────────────────┘                        │
│                  │ 제안(검증 전)                         │ 구조화된 교육 이벤트                            │
│                  ▼                                       ▼                                                 │
│   ┌─────────── World Engine (규칙 · 결정론) ───────────┐   ┌──────── Learning Core (PyTorch) ────────┐     │
│   │ 전제조건 검사 → 결과 확정 → 이벤트 로그 append     │──▶│ Tokenizer · TinyTransformer              │     │
│   │ 상태 = fold(이벤트 로그)  (event sourcing)          │   │ Online Learner · Evaluator · Checkpoints  │     │
│   │ 아이에게 공개할 관찰(Observation) 생성              │◀──│ act(observation) → 행동 토큰             │     │
│   └─────────────────────────────────────────────────────┘   └──────────────────────────────────────────┘     │
│                         │                                              │                                   │
│                    saves/<save_id>/  events.jsonl · dataset.jsonl · ckpt_*.pt · journal.jsonl              │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 권한 경계 (가장 중요한 설계 규칙)

| 구성 | 할 수 있는 것 | 절대 못 하는 것 |
|---|---|---|
| Director | 사건 계열·관련 ID·전제조건·공개 관찰 **제안** | 상태 변경, 아이 행동/성공 결정 |
| Narrator | 확정된 이벤트를 텍스트로 표현 | 새 물건·사실·아이의 내면 추가 |
| Interpreter | 부모 문장을 `TeachEvent` 스키마로 변환, 모호하면 되묻기 | 부모가 말하지 않은 지식 주입 |
| Tutor | 이미 가르친 개념의 복습 변형 / 실행 로그 기반 일지 문장 | 평가셋 정답 노출, 가르치지 않은 개념 생성 |
| World Engine | 상태 확정의 **유일한** 주체 | LLM 문장으로 규칙 변경 |
| Child model | 공개 관찰만 보고 행동 토큰 출력 | Meta API 호출 (코드상 import 자체 금지) |

`learning/` 패키지는 `agents/` 를 import 하지 못하게 테스트로 강제한다(우회 차단의 구조적 증거 → 데모에서 보여줄 수 있음).

### 2.2 Event sourcing을 쓰는 이유

- 세계 상태 = 이벤트 로그를 순서대로 접은 결과. 저장/재개 일치가 자동으로 보장된다.
- 각 행동에 `action_id`(idempotency key) → 동일 행동 재전송 시 이중 적용 방지.
- "물 쏟음 → 바닥 젖음 → 닦기 기회" 같은 후속 사건은 로그 조회로 자연스럽게 구현.
- 성장 일지는 로그에서 **사실만** 뽑아 만든다 (환각 방지).

## 3. 세계 (World Engine)

### 3.1 MVP 범위
- 장소 2: `house`, `yard` (이동 경로 시뮬레이션 없음, 장면 전환만)
- NPC 1: 이웃 할머니/선생님 역할 (퀴즈 담당 = Eval의 게임 내 얼굴)
- 물건 6~8 종류, 각 종류는 **여러 개체**(색·크기 변형)로 등장 → 범주 일반화 평가 가능
- 사건 계열 4: `discovery`(발견) · `chore`(생활 문제) · `visit`(방문) · `followup`(이전 사건의 후속)
- 게임 내 3일, 하루 = 아침 → 상황 6개(선택 → 즉시 학습) → 저녁 퀴즈·기록

### 3.2 데이터 모델 (초안)

```python
ObjectKind   = {id, category_hidden, affordances: [drink, wipe, light, ...]}   # category는 아이에게 비공개
ObjectInst   = {id, kind_id, color, shape, size, material, location, qty, state}
WorldState   = {day, phase, location, objects{}, npc_location, open_issues[], resolved[], names{}}
Event        = {seq, action_id, type, payload, preconditions, effects, ts}
Observation  = {location, situation_flags[], slots: [visible attrs ×N], request}  # 아이에게 주는 유일한 입력
```

### 3.3 한 턴 처리
1. 상태·미해결 사건 로드
2. Director가 `EventProposal` JSON 제안 (실패/타임아웃 → 검증된 사건 템플릿으로 대체)
3. Engine이 전제조건 검사 (존재·위치·수량·중복·해결 여부). 실패 시 1회 재제안 → 템플릿
4. Observation 생성 (선택지에 정답만 남기지 않음, 방해 물건 포함)
5. 부모 교육 또는 아이 행동 수신 → Engine이 결과 확정 → 로그 append
6. Narrator가 확정 사실을 서술 → 참조 검사(언급된 물건 ID가 실제 존재하는가) 실패 시 고정 문구
7. 아이가 **실제로 경험한 것만** 리플레이 버퍼로

### 3.4 물건 확정표 (7종)

종류를 정하는 **정의 속성**(모양·재질)은 고정, **표면 속성**(색·크기)은 개체마다 바뀐다. 아이는 종류 이름을 모르고 속성만 본다.

| 종류 (비공개) | 정의 속성 | 표면 속성 변형 | 쓰임 | 비고 |
|---|---|---|---|---|
| cup | `SHAPE_CYL` `MAT_CERAMIC` | 색 4 · 크기 2 | `ACT_DRINK` | |
| cloth | `SHAPE_FLAT` `MAT_FABRIC` | 색 4 · 크기 2 | `ACT_WIPE` | |
| paper | `SHAPE_FLAT` `MAT_PAPER` | 색 2 | (닦으면 찢어짐) | cloth와 모양이 같은 **함정** |
| blanket | `SHAPE_FLAT` `MAT_WOOL` | 색 3 · 항상 `SIZE_BIG` | `ACT_COVER` | 모양 같고 재질·크기로 구분 |
| flashlight | `SHAPE_TUBE` `MAT_METAL` | 색 3 | `ACT_LIGHT` | |
| spoon | `SHAPE_LONG` `MAT_METAL` | 색 2 · 크기 2 | (방해 물건) | flashlight와 재질 같음 |
| ball | `SHAPE_SPHERE` `MAT_RUBBER` | 색 4 · 크기 2 | `ACT_GIVE` | 방문 사건에서 선물 |

일부 종류가 모양이나 재질을 공유하도록 일부러 겹쳤다. 속성 하나만 외워서는 못 푸는 문제가 생겨야 학습이 의미 있다.

### 3.5 상황 → 행동 (놀이 B)

| 상황 플래그 | 맞는 행동 | 틀린 선택의 결과 (엔진 규칙) |
|---|---|---|
| `THIRSTY` | `ACT_DRINK` + cup | 그대로 목마름 → 저녁에 기운 없음 |
| `FLOOR_WET` | `ACT_WIPE` + cloth | paper로 닦으면 paper 수량 −1, 바닥 여전히 젖음 |
| `DARK` | `ACT_LIGHT` + flashlight | 아무 일 없음, 밤 사건 일부 불가 |
| `COLD` | `ACT_COVER` + blanket | 다음 날 아침 `SNEEZE` 플래그 |
| `NPC_HERE` | `ACT_GIVE` + ball | 방문이 짧게 끝남 |

### 3.6 이야기 연쇄 (과거 사건이 다음 사건을 만든다)

고정 줄거리가 아니라, **엔진 규칙이 만든 후속 기회**들이다. Director는 이 중 전제조건이 맞는 것을 고르고 살을 붙인다.

```
[chore] 물을 쏟음 ──▶ FLOOR_WET
   ├─ 닦음(cloth) ──▶ 할머니 방문 때 칭찬 ──▶ [discovery] 공(ball) 선물 → 새 물건, 새 이름 가르칠 기회
   ├─ paper로 닦음 ──▶ paper 찢어짐, 여전히 젖음 ──▶ 다음 장면에 다시 기회 (1회)
   └─ 방치 ──▶ [visit] 할머니가 미끄러질 뻔 ──▶ 할머니가 cloth 위치를 알려줌 (발화 기록)

[chore] 정전 ──▶ DARK
   ├─ flashlight 켬 ──▶ [discovery] 마당에서 새 물건 발견
   └─ 실패 ──▶ 그날 마당 사건 불가

[weather] 추운 밤 ──▶ COLD ──▶ 덮지 않으면 다음 날 SNEEZE ──▶ 할머니가 blanket 가져옴
```

아이의 성공이 **새 물건과 새 사건을 연다** → 배운 게 세계를 넓힌다. 실패도 막다른 길이 아니라 다른 갈래로 이어진다.

## 3A. 게임 루프 상세

### 3A.0 핵심 루프: 상황 → 선택 → 학습

```
Director(Meta)가 상황 카드 2장 제안 → 엔진 검증·확정 → 플레이어가 1장 선택
  → 상황 시작 (요청 + 물건들)
  → 플레이어가 이 상황에서 할 행동을 선택 = 시범(Show)
  → 엔진이 결과 확정(세계 변화) → 선택이 Example로 기록
  → 즉시 학습 스텝 (아이 모델 가중치 갱신)
  → 이후 상황에서 아이가 스스로 시도(Try) → 플레이어가 칭찬/교정 → 다시 학습
```

- 플레이어의 선택이 곧 학습 데이터다. 수면 학습은 없다
- 정보 비대칭: 플레이어는 물건 종류 라벨까지 보고, 아이는 속성만 본다
- 플레이어가 틀린 행동을 골라도 그대로 학습한다(결과는 세계에 반영) — 데이터 품질이 아이를 만든다
- 한 상황은 `Show` / `Try`(+칭찬·교정) / `Skip` 중 하나로 한 번만 해결된다. Skip은 학습 없음

### 3A.1 하루 (약 5분 × 게임 내 3일 = 15~20분)

| 구간 | 시간 | 내용 |
|---|---|---|
| 아침 | 20초 | 어제 결과가 반영된 장면 서술 + 성장 일지 한 줄 (사실만) |
| 상황 ×6 | 4분 | 카드 2장 중 선택 → 행동 선택 또는 아이에게 시키기 → 즉시 학습 |
| 저녁 | 40초 | 할머니 퀴즈 3문제 (평가셋, **학습에 안 씀**) + 어제 점수와 비교 + 체크포인트 스냅샷 |

### 3A.2 플레이어 행동

| 행동 | 무엇이 일어나나 | 학습 데이터 |
|---|---|---|
| 카드 선택 | 제안된 상황 2장 중 1장 시작 | — |
| 행동 선택 (Show) | 슬롯 하나를 골라 요청을 수행. 틀려도 허용 | O — 가중치 1.0 |
| 아이에게 시키기 (Try) | 아이 모델이 직접 행동, 엔진이 결과 확정 | 피드백에 따라 |
| ↳ 칭찬 | 맞은 행동 확정 | O — 가중치 0.5 |
| ↳ 교정 | 틀렸을 때 맞는 슬롯을 보여줌 | O — 1.0 + (선택, 거절) 쌍 |
| 건너뛰기 (Skip) | 상황 종료 | X |

1일 차 첫 상황은 **고정 튜토리얼 상황**(LLM 미사용)으로 시작하고, 이후부터 Director가 카드를 구성한다. 학습 지연이 길면 하루 끝 배치 학습으로 후퇴하는 방안이 SKELETON.md의 D1 게이트에 있다.

## 4. 메인 캐릭터 (Learning Core)

### 4.1 토큰 체계 (초안, ~120 토큰)

| 그룹 | 예 |
|---|---|
| 특수 | `[BOS] [SEP] [EOS] [PAD] [MASK]` |
| 맥락 | `LOC_HOUSE LOC_YARD NPC_HERE` |
| 상황 | `THIRSTY FLOOR_WET DARK COLD ...` |
| 속성 | `COLOR_* SHAPE_* SIZE_* MAT_*` (~20) |
| 슬롯 | `SLOT_0 … SLOT_4` |
| 요청 | `REQ_FIND REQ_USE REQ_FREE` |
| 이름 | `NAME_00 … NAME_31` — 플레이어가 지은 단어를 세이브별로 바인딩 |
| 행동 | `ACT_PICK ACT_DRINK ACT_WIPE ACT_LIGHT ACT_COVER ACT_GIVE ACT_WAIT` |

예시 (놀이 A: 이름 알아듣기)
```
입력:  [BOS] LOC_HOUSE REQ_FIND NAME_03 [SEP] SLOT_0 COLOR_BLUE SHAPE_FLAT SIZE_BIG [SEP]
       SLOT_1 COLOR_RED SHAPE_ROUND SIZE_SMALL [SEP] SLOT_2 ... [SEP]
출력:  ACT_PICK SLOT_1 [EOS]
```
- 입력에 숨은 category·정답 표시 없음. 이름↔속성 연결을 학습으로만 익힘
- 문법 제약 디코딩: 문법상 가능한 행동·**존재하는 모든 슬롯**만 허용 (정답 슬롯만 남기지 않음)
- 화면에는 출력 토큰을 고정 문구로 매핑 ("빨갛고 동그란 걸 집었다"). LLM으로 꾸미지 않음

### 4.2 모델
- Decoder-only Transformer, 무작위 초기화. 시작점 `d=128, layers=2–4, heads=4` → **약 0.3M~1.5M 파라미터**
- 시퀀스 길이 ≤ 64. CPU에서도 학습 가능한 크기 → 호스팅 비용·이식성 확보 (MPS는 가속 옵션)

### 4.3 학습 스텝 (Online Learner)
- 트리거: 플레이어의 Show / 칭찬 / 교정 직후 (수면 없음)
- 배치 = 새 Example(오버샘플) + 과거 버퍼 replay k개(망각 방지). 소수 step(예: 30)
- 증강: 슬롯 순서 셔플만. 표면 속성(색·크기)은 바꾸지 않음 (4.5 참조)
- 대신 Director가 같은 종류의 다양한 개체를 등장시켜, 플레이어가 다양성을 **보여줄 기회**는 항상 있게 한다
- 손실 = SFT CE (행동 토큰만). 관찰 마스킹 보조 손실은 stretch
- 목표 지연 ≤ 2초 (M5 Pro). 미달 시 step·모델 크기를 줄이거나 하루 끝 배치 학습으로 후퇴
- 학습마다 `latest.pt` 갱신, 하루 끝에 `day_NN.pt` 스냅샷. `ckpt_000.pt`는 불변. loss 변화는 화면에 즉시 표시

### 4.4 평가 (Evaluator)
- 평가셋은 생성 시점부터 학습 버퍼와 분리 (새 배치·새 방해 물건·같은 범주의 새 개체)
- 비교군: ① 무작위 기준(1/슬롯 수) ② **학습 비활성 대조** (같은 init, 업데이트 없음) ③ 시드 3개
- 리셋 검사: `ckpt_0`으로 되돌리면 성과가 사라지는지 → 엔진/문맥 우회가 없다는 증거
- 망각 검사: 놀이 B 학습 후 놀이 A 정답률 하락 ≤ 10%p

**정답의 정의**: 플레이어가 지은 이름의 정답은 "이름을 붙일 때 가리킨 물건의 **종류**"다. 종류는 엔진만 알고, 아이 입력·Interpreter 출력에는 들어가지 않는다. 퀴즈는 그 종류의 **새 개체**(다른 색·크기) + 새 배치 + 함정 물건으로 낸다. 따라서 플레이어가 빨간 컵만 보여줬다면 퀴즈에서 틀릴 수 있다 — 이것이 1.2의 재미이며, 일지에 "파란 컵은 아직 뽀뽀인 줄 모름"처럼 사실로 남는다.

### 4.5 학습 데이터 출처 규칙

| 출처 | 학습 사용 | 비고 |
|---|---|---|
| 플레이어가 상황에서 고른 행동 (Show) | SFT, 가중치 1.0 | 틀린 선택도 그대로 학습 |
| 교정 | SFT 1.0 + (선택, 거절) 쌍 | 쌍은 DPO-lite(stretch)용으로 저장만 먼저 |
| 칭찬받은 아이 행동 | SFT 0.5 | 자기 행동 강화 |
| 칭찬·교정 없는 아이 행동 | **사용 안 함** | 틀린 행동을 스스로 강화하는 것 방지 |
| 장면 관찰 전체 | 관찰 마스킹 예측 (pretraining) | 정답 행동 없음 |
| 증강 예시 | 원본의 가중치 상속 | 슬롯 셔플·방해 물건 재추첨만. **표면 속성은 바꾸지 않음** |
| 할머니 퀴즈 | **절대 사용 안 함** | 평가셋 해시를 학습 전 대조해 누출 검사 |

증강에서 표면 속성(색·크기)을 바꾸지 않는 이유: 바꾸면 플레이어가 안 보여준 다양성을 코드가 몰래 채워 넣는 셈이 되어, 1.2의 "가르친 방식대로 자란다"가 거짓이 된다. 배치·방해 물건만 바꾼다.

### 4.6 "아이 머릿속" 패널 (모델 탐침)

학습 전후로, 배운 이름·상황마다 **실제 모델을 통제된 탐침 장면에 돌려** 무엇에 반응하는지 보여준다. LLM이 쓴 설명이 아니라 측정값이다.

```
"뽀뽀"라고 하면 고르는 것          (탐침 장면 60개 기준)
  원통 모양       ████████████░░  82%
  도자기          ██████████░░░░  71%
  빨간색          ████████░░░░░░  58%   ← 빨간 컵만 보여줘서 생긴 편향
  큰 것           ███░░░░░░░░░░░  21%
```

- 탐침: 한 속성만 다르고 나머지는 같은 물건 쌍을 보여주고 선택 확률을 측정 (contrast probe)
- 학습 전후 막대가 바뀌는 애니메이션 = "학습이 실제로 바꾼 것"의 시각적 증거
- 개발 비용이 작다(평가기 재사용) 대비 데모 효과가 커서 MVP에 포함
- **v1에서 구현·검증됨** (v1 스냅샷 `archive/v1_skeleton_2026-10-26.tar.gz`의 `probe.py`): 좁게 가르친 아이는 red 선호 0.79~0.92, 다양하게 가르친 아이는 0.50으로 실제 차이가 측정됨. 상세는 SKELETON.md 11장
- **v2 엔진에서는 아직 없음**: 현재 `Session.mind`는 주제별 정확도와 태그 의존(tag-reliance)만 보여준다. 속성·동사 대비 탐침을 옵션 입력에 맞게 다시 만드는 일은 WORLD.md 13장의 남은 일에 있다

## 5. Meta 서브에이전트 상세

공통: 하나의 `MetaClient` (엔드포인트·인증은 대회 시작 후 API 문서로 확정. OpenAI 호환이면 그대로, 아니면 어댑터). 모든 응답은 **JSON Schema 강제 + pydantic 검증**, 실패 시 재시도 1회 → 템플릿 폴백. 프롬프트·응답 전부 로그 저장(데모·디버깅용).

### 5.1 모델 라우팅 (폴백 체인)

```
muse-spark-1.3-contributor  ──(오류/타임아웃/속도 제한)──▶  muse-spark-1.2-contributor
        ──(둘 다 실패)──▶  Meta 오픈웨이트 모델 @ 파트너 (Fireworks/Baseten, OpenAI 호환)
        ──(그것도 실패)──▶  검증된 템플릿 / 고정 문구
```

- 에이전트별 모델은 설정 파일 한 곳(`agents/models.yaml`)에서 바꾼다. 코드에 모델명 하드코딩 금지
- 파트너 폴백도 **Meta 모델**이므로 "Meta 모델로 만든 프로젝트"라는 조건이 유지된다
- 기여자 모드 이용 조건(입력 데이터 처리 방식 등)은 1일 차에 확인하고, 플레이어 입력이 전송된다는 점을 시작 화면에 고지한다

| 에이전트 | 입력 | 출력 스키마 | 모델 | 폴백 |
|---|---|---|---|---|
| Director | 상태 요약, 미해결 사건, 최근 로그 | `EventProposal{family, refs[], preconds[], links_to, observation_hint}` | `muse-spark-1.3-contributor` | 사건 템플릿 테이블 |
| Narrator | 확정 이벤트 + 참조 객체 | `{text, referenced_ids[]}` | `muse-spark-1.3-contributor` (지연이 크면 1.2 비교 후 선택) | 고정 문구 |
| Interpreter | 부모 자유문장 + 현재 장면 | `TeachEvent{kind: name/demo/correct, target_slot, name_word, action}` 또는 `{clarify}` | `muse-spark-1.3-contributor` | 버튼식 교육 UI |
| Tutor | 가르친 개념 목록, 실행 로그 | `{review_concepts[]}` / `{journal_lines[] with event_refs}` | `muse-spark-1.3-contributor` | 로그 템플릿 문장 |
| (선택) Art | 물건 종류·속성 | 아이콘 이미지 | Muse Image | 이모지/SVG |

**Interpreter는 뼈대에서 제외**: 플레이어는 자연어 대신 상황의 선택지(슬롯)를 고른다. 자유문장 입력("컵을 줄게")을 행동 선택으로 바꾸는 용도로 후반에 선택적으로 붙인다. 핵심 서브에이전트는 **Director(상황 카드 생성)** 이며, 자연스러운 상황·대사는 Meta가, 실제 학습은 작은 모델이 맡는 경계는 같다.

Muse Image는 **빌드 타임에 한 번** 물건 아이콘을 생성해 캐시 (런타임 의존 없음). 시간 남을 때만.

## 6. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|

## 8. 데모 (3분) 시나리오

1. **0:00** 컨셉 한 줄 + "LLM 개발 파이프라인 = 육아" 대응표 (5초 컷)
2. **0:20** 갓 태어난 아이: 이름 불러도 아무거나 집음 (random init)
3. **0:45** Director가 상황 카드를 제시 → 플레이어가 행동을 선택(시범) → 세계가 반응
4. **1:15** 선택 직후 실제 학습이 돌고 loss가 내려감, 머릿속 패널에서 "빨간색" 편향이 보임 (라이브 학습임을 명시)
5. **1:35** 파란 컵 상황도 시범 → 편향이 "원통 모양"으로 옮겨감
6. **1:55** 다음 날: 처음 보는 초록 컵을 맞게 집음 → 그 행동이 후속 사건을 바꿈
7. **2:15** NPC 퀴즈 = 벤치마크. 대조군·무작위 대비 정답률, `ckpt_0`으로 되돌리면 다시 모름
8. **2:40** 저장/재개 후 유지 + 구조 다이어그램(Meta = 세계, 작은 모델 = 아이)

준비 학습한 체크포인트를 쓰는 구간은 화면에 표시하고, 라이브 학습 구간과 구분한다.

## 10. 리스크

| 리스크 | 대응 |
|---|---|
| 플레이 중 시범 데이터가 너무 적음 (수십 개) | 프로그램 증강 + replay. 놀이 A는 범주 수가 작아 소량으로도 학습 가능성 높음 — D1에 수치로 확인 |
| 표면 속성 증강을 안 해서 학습이 너무 어려움 | D2 게이트 ②에서 확인. 안 되면 하루 상황 수를 늘리거나 물건 종류를 줄임 (증강으로 몰래 채우지 않음) |
| 플레이어가 편향을 버그로 오해 | 머릿속 패널 + 일지 문구 + 튜토리얼에서 "다양하게 보여주세요" 힌트 |
| 작은 모델 출력이 밋밋해 보임 | 세계·서술·학습 시각화가 풍성함을 담당. 아이의 출력은 일부러 단순 — 그게 "진짜"라는 증거 |
| Meta API 지연/장애 | 1.3 → 1.2 contributor → 파트너 오픈웨이트 → 템플릿 순 폴백, 응답 캐시. 데모는 LLM 없이도 진행 가능해야 함 |
| API가 대회 시작 후에야 열림 | D0~D1 오전은 API 없이 진행 가능한 작업(학습 실험·엔진)부터. `MetaClient`는 목(mock) 응답으로 먼저 개발 |
| LLM이 상태를 망가뜨림 | 제안만 허용, 확정은 엔진. 참조 검사 실패 시 고정 문구 |

| 일정 지연 | 7.1 사다리, D8 기능 동결 |
